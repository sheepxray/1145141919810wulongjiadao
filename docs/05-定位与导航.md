# 05 · 定位与导航

> **本文包含对本仓库早期版本的一处重要更正。** 早期版本声称挡板测距公式
> "与相机高度和俯仰角无关"，该推导有误。所有数值均可用 `python tools/geometry.py` 复现。

---

## 1. 精度需求的正确分解

先明确一件事：**全局定位的精度要求其实很低。**

推入方向由两部分决定：

```
推入方向 = 棋子相对车体的方位 (下视相机)  +  车体绝对航向 (IMU)
```

注意 **"棋子的绝对坐标"从来没有出现在这个公式里**。全局定位只需要精确到：

- 知道球门在哪个方向（±10° 足够）；
- 知道附近有没有棋子（±50mm 足够）。

而真正要求精度的是：
- **航向**：IMU，±0.5°；
- **棋子相对车体的方位**：下视相机，±3mm 级（因为读字时车是静止的，距离近）。

**这个分解是本方案敢用纯航迹推算而不上激光雷达的根本原因。**

---

## 2. 挡板测距的完整几何（含更正）

### 2.1 正确公式

设：相机光心高 `h`，俯仰角 `θ`（向下为正），挡板高 `H`，水平距离 `d`，像素焦距 `f`。

```
挡板底(地面)的俯角   α_bot = atan(h / d)
挡板顶(80mm高处)的俯角 α_top = atan((h − H) / d)

像素间距 Δy = f · [ tan(α_bot − θ) − tan(α_top − θ) ]
```

### 2.2 更正内容

| 说法 | 是否成立 |
|---|---|
| "与**相机高度**无关" | ✅ 仅在 **θ = 0** 成立 |
| "与**俯仰角**无关" | ❌ **不成立** |

`θ = 0` 时 `Δy = f·H/d`，高度 `h` 确实被消掉。
但 `θ ≠ 0` 时上述化简不成立。

### 2.3 实跑数据（`tools/geometry.py`）

相机 OV5640 + 2.8mm（f = 2000 px）：

| h | θ | 真值 d | 近似式 `H·f/Δy` 反解 | 误差 |
|---|---|---|---|---|
| 150mm | 0° | 0.50m | 0.500 | 0.0% |
| 150mm | 10° | 0.50m | 0.523 | +4.6% |
| 150mm | 20° | 1.50m | 1.396 | **−6.9%** |
| 150mm | 30° | 0.50m | 0.476 | −4.9% |
| 250mm | 10° | 0.50m | 0.559 | **+11.9%** |
| 250mm | 20° | 0.50m | 0.586 | **+17.3%** |
| 250mm | 30° | 1.50m | 1.314 | **−12.4%** |

**最大误差 17.3%。相机越高、俯角越大，误差越大。**

### 2.4 实现规范

**本仓库一律使用完整投影的数值反解**，不使用近似式：

```python
def solve_range_from_pixels(cam, h, theta, dy_px, wall_h=0.08):
    """已知像素间距 dy，反解水平距离 d（二分法，单调安全）"""
    lo, hi = 0.02, 60.0
    for _ in range(200):
        mid = 0.5 * (lo + hi)
        dep_top = math.degrees(math.atan((h - wall_h) / mid))
        dep_bot = math.degrees(math.atan(h / mid))
        y_top = cam.pixel_y(dep_top, theta)
        y_bot = cam.pixel_y(dep_bot, theta)
        if (y_bot - y_top) > dy_px:
            lo = mid
        else:
            hi = mid
    return 0.5 * (lo + hi)
```

C 端移植注意：二分 200 次在 MCU 上开销大。实际只需 **20 次**（精度已到 1e-6），
或者用查表 + 线性插值（标定时生成 256 点表）。

## 3. 量程结论：只能做近场

即便用正确的反解，测距精度仍随距离平方恶化（边缘定位噪声 2px）：

| 距离 | 像素间距 | 测距不确定度 | 用途 |
|---|---|---|---|
| 0.3m | 474 px | **±2.2mm** | 优 |
| 0.5m | 306 px | **±5.2mm** | 优 |
| 0.8m | 199 px | ±12.2mm | 优 |
| 1.0m | 162 px | ±18.5mm | 可用 |
| 1.5m | 110 px | ±40.1mm | 可用 |
| 2.0m | 83 px | ±70.0mm | 差 |
| 2.5m | 67 px | ±108.1mm | 差 |
| 3.0m | 56 px | **±154.4mm** | **不可用** |

### 由此否决全场挡板 PnP

原计划的"检测墙体四边形对 3m×2m 矩形做 PnP 求解 6DOF 位姿"被**否决**，理由：

1. **远场精度不可用**（3m 处 ±154mm，比全局需求 ±50mm 还差 3 倍）；
2. **退化**：只看得到 1 面墙时 PnP 退化；两条平行墙无法定 6DOF；
3. **遮挡**：对方车和棋子会挡住墙角，而墙角恰是最需要的时候；
4. **识别"这是哪面墙"本身需要先知道朝向 —— 鸡生蛋问题**；
5. **反光与低对比**：亮面墙、墙与地同色时，边缘检测不稳定。

### 而贴墙纵推需要 ±10mm —— 也不来自视觉测墙

见第 4.3 节的"贴墙纵推"模式：**横向精度靠机械贴墙 + ToF 闭环，不靠视觉**。

## 4. 分层定位架构

### 4.1 第 0 层：航迹推算（始终运行）

```
θ(k+1) = θ(k) + ω_gyro · dt                 （IMU 陀螺积分）
x(k+1) = x(k) + v · cos(θ) · dt             （编码器里程计）
y(k+1) = y(k) + v · sin(θ) · dt             （差速模型）
```

- **陀螺零偏**：上电静止 1 秒标定；由撞墙重定位周期性校正。
- **轮径标定**：跑 3m 直线，用实测距离反算有效轮径，**不要用游标卡尺量的轮径**
  （轮胎压缩、打滑都会让有效轮径不同）。
- **预期漂移**：3 分钟内、短路径，漂移几十 mm 到几百 mm。足够支撑"知道球门在哪个方向"。

### 4.2 第 1 层：撞墙重定位（★ 最强的锚点）

**关键洞察：每次把棋子推入球门，都必然贴近端墙。**

把"贴墙即重定位"写进状态机：

| 触发 | 动作 |
|---|---|
| 检测到贴墙（堵转 + 前视测距 < 阈值） | 把**沿墙法向的位置**清零 |
| 同时 | 把**相对墙的航向**清零 |

这是**零成本、零算力**的绝对基准 —— 比任何视觉标定都稳定，
因为它是机械接触，不受光照、反光、遮挡影响。

**实现**：靠墙时电机堵转（见 [docs/03](03-电控与驱动系统.md) 第 5 节），
堵转信号 + 前视相机测距值共同确认"确实贴墙"而非"被对方车挡住"。

### 4.3 第 2 层：近场测墙（辅助）

前视相机在 **0.3–1.0m** 范围测挡板（精度 ±2 到 ±18mm），用于：
- 推入前对正端墙；
- 退出球门区时确认距离;
- 侧向：**贴墙纵推模式**靠墙走时保持固定距离。

**超过 1m 不使用。**

### 4.4 第 3 层（可选）：侧向 ToF

加 1 个 VL53L1X（约 ¥25）朝侧面，提供横向近场距离（精度 ±5mm @ 1m）。
用于贴墙纵推时的横向闭环。

**这是唯一一个"视觉测墙精度不够、机械贴墙又太粗"场景的补丁。** 预算内可加。

## 5. 贴墙纵推模式

### 5.1 为什么需要它

棋子贴侧墙时，由 [docs/02](02-机械系统设计.md) 第 3.2 节，推板罩住棋子的窗口很窄。
但比窗口更根本的问题是：**推入方向吸附到长轴后，如果棋子就在墙上，车也没法站到它正后方。**

### 5.2 做法

不要试图把车居中到棋子正后方。改为：

```
1. 让车**侧面贴着侧墙**走（用 ToF/测距把"车侧—墙"距离锁在固定值）
2. 此时推板的**悬伸部分**恰好覆盖贴墙的那枚棋子
3. 沿墙纵推 3m 进入端墙球门
```

**横向精度由传感器闭环保证，不需要开环对准到 ±40mm。**

### 5.3 风险与限制

⚠️ **贴侧墙纵推 3m 会显著提高"把棋子拱进对面球门"的概率。**

因为推进方向恒指向己方球门，若棋子已在对方半场，纵推会把它推向对方门 = **送分**。

**限制条件**：贴墙纵推**只在棋子已在己方半场时**才执行。
否则跳过该棋子，标进地图，不再尝试。

## 6. 里程计标定流程

| 步骤 | 做法 | 目标 |
|---|---|---|
| 1 | 轮径标定：跑 3m 直线，反算有效轮径 | 线性误差 < 1% |
| 2 | 轮距标定：原地转 10 圈，反算有效轮距 | 角度误差 < 2% |
| 3 | 陀螺零偏：静止 60 秒，记录均值与漂移 | 漂移 < 0.5°/min |
| 4 | 直线行走测试：走 3m，记录横向偏差 | < 50mm |
| 5 | 方形路径测试：走 1m×1m 方框回到原点 | 闭合误差 < 100mm |

**第 4、5 步在真实场地地面上做**，不能在光滑桌面做（摩擦系数完全不同）。

## 7. 失效模式与对策

| 失效模式 | 后果 | 对策 |
|---|---|---|
| 陀螺零偏漂移 | 全局航向慢偏 | 撞墙重定位周期性清零 |
| 轮子打滑（棋子/灰尘） | 里程计跳变 | 加速度一致性检验，剔除异常里程增量 |
| 挡板反光/低对比 | 近场测距失败 | 降级：仅用航迹推算 |
| 对方车遮挡视野 | 短暂丢失定位 | 靠航迹推算"盲走"，避让优先 |
| **K230 brownout 重启** | 视觉全丢 + 定位跳变 | 电源隔离（见 docs/06）；重启后进降级策略 |
| 贴墙误判（被对方车挡住） | 位置被错误清零 | 堵转 + 测距双条件确认 |
| 编码器线被撞断 | 单轮失控 | 上电自检 + 运行时单轮异常检测 |

## 8. 为什么不用激光做定位

| 理由 | 说明 |
|---|---|
| 看不见 | 1mW 650nm 一字线在明亮体育馆 3m 处几乎不可见 |
| 滤光片悖论 | 要靠 650nm 窄带滤光片抗环境光，但加了之后就**只能看见激光**，等于毁掉正常视觉通道 |
| 标定依赖 | 结构化光精度取决于激光器-相机基线标定，漂移后全盘失效 |
| 性价比 | 1 个 ToF（¥25）能做的事，不值得用激光 + 标定去换 |
| **合规风险** | 不应把激光指向对方车辆或人员 |

**激光只为满足 C9"必须搭载"**：串限流电阻、实测 ≤0.7mW、低位向前安装、清晰标识。

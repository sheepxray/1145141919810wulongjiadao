# 01 · 总体方案

> ⚠️ **方案裁决（2026-09-28）**：仓库已按实际采购定为 **麦轮全向 + K230D + 单 OV5640 + STM32G474 + TB6612**（见 [08 BOM](08-BOM物料清单.md)、[16 商品清单](16-最终商品清单.md)、[10 计划](10-开发计划与里程碑.md)）。本文为早期/旧平台版本，其中与当前采购冲突的选型与指标以 16/17 为准；架构思路与算法结论多数继续沿用。

## 1. 系统架构

```
┌──────────────────────── K230 视觉协处理器 ────────────────────────┐
│                                                                    │
│   前视相机 (俯角15°)              下视相机 (俯角60°)                │
│     · 棋子搜索：颜色阈值 + 轮廓      · 停车读字：小 CNN 分类         │
│     · 近场测墙：挡板上下边缘          · 推入段伺服：保持棋子居中      │
│     · 对手车/障碍：大色块检测         · 落位确认：棋子是否进区        │
│                                                                    │
│              输出：结构化的目标列表 + 相对方位 + 类别               │
└──────────────────────────────┬─────────────────────────────────────┘
                               │ UART 921600, ~10Hz
                               │ 帧格式见 docs/11
┌──────────────────────────────┴─────────────────────────────────────┐
│              STM32G474VET6 运动主控（170MHz）                         │
│                                                                     │
│   · 4 路编码器正交解码 (TIM)        · 4 路 PWM 20kHz (TIM)          │
│   · ICM20602 (SPI2) 航向积分         · 双环 PID: 速度环 + 航向环     │
│   · 航迹推算 EKF                     · 状态机 (docs/07)              │
│   · 堵转检测与保护                   · 上电自检                      │
└──────┬──────────────────────────────────────────────┬──────────────┘
       │                                              │
  TB6612 四路 D24A                               电源系统
       │                                              │
  MG513X ×4（麦轮全向）                    3S LiPo → 12V / 5V / 3.3V
```

## 2. 为什么这样切分

| 决策 | 理由 |
|---|---|
| 视觉与运动分离 | CNN 推理需 NPU（STM32 跑不动）；1kHz 硬实时需 MCU（Linux 给不了） |
| 耦合只有一个串口 | 接口面最小 = 调试最容易。10Hz 的"目标列表"足够低频，不必上高速总线 |
| K230 不做电机控制 | CanMV 的 RT-Smart + Linux 混合调度不具备 1kHz 确定性 |
| 相机分成两个 | 见 [docs/02](02-机械系统设计.md) 第 5 节：垂直下视的可见区间只有 0–76mm，覆盖不到推板前方；而看远墙与近场读字的几何需求方向相反 |

## 3. 数据流

```
[前视帧] → 颜色阈值分割 → 连通域 → 棋子候选 (图像坐标 + 颜色)
                                    ↓
                          [车体坐标变换] → 候选列表
                                    ↓
                          [目标打分函数] (docs/07)
                                    ↓
                          选中目标 → 生成接近路径
                                    ↓
[停车] → [下视帧] → 小 CNN → 分值 + 是否帅/将  → 更新该棋子类别
                                    ↓
                          两段式接近 → 第二段下视伺服 → 推入
                                    ↓
                          [撞墙重定位] → 位姿清零 → 下一个目标
```

## 4. 方案选型对比

### 4.1 底盘

> ⚠️ **本节记录选型论证的演变**：设计阶段论证偏向差速，但**实际采购为麦轮全向**。
> 两段都保留，便于追溯；**以「实际采用」一行为准**。

**设计阶段的论证（差速胜出）**：

| 方案 | 优点 | 缺点 | 阶段结论 |
|---|---|---|---|
| **差速 + 侧裙推板** | 2 电机；成本/质量/故障点减半；3D 打印易实现 | 微调方向需转向 | ✅ 阶段采用 |
| 麦克纳姆轮全向 | 可平移；对准与推入解耦 | 4 电机；3D 打印辊子质量差；受推力时侧向漂移污染推入段；**不改变车宽，解决不了贴墙问题** | ❌ |
| 履带 | 抓地好 | 转向滑移大、里程计差；3D 打印履带易断 | ❌ |

**决定性理由（当时）**：反对差速的核心理由是"转向时推板会把棋子甩出"，
但**侧裙从机构上消掉了这个理由**，而麦轮解决不了真正的问题（车宽）。
推导见 [docs/02](02-机械系统设计.md) 第 3.2 节。

**→ 实际采用：麦克纳姆轮全向（4×MG513X）**

变更原因是**采购口径变化**，不是论证被推翻：

| 影响 | 说明 |
|---|---|
| 有利 | 全向平移让「对准」与「推入」解耦，贴墙横移更容易 |
| ⚠️ 新增风险 | **航向 θ 的解算变难**——麦轮的 ω 由四轮转速差分得出，横移时辊子滑移不对称会产生虚假 ω。本任务精度压力恰集中在航向，故 **IMU 仍需（可后置）**，论证见 [docs/10](10-开发计划与里程碑.md) |
| ⚠️ 质量 | 4 电机占 **680g**，逼近 1500g 上限的 45%，结构件预算被压缩到约 600g |
| ⚠️ 驱动 | TB6612 持续 1.2A/通道，4 轮同时堵转超标 → **堵转保护必须做** |
| 不变 | 「车体做窄 + 推板做宽」的贴墙容错结论**仍然成立**（与轮系无关） |

### 4.2 定位

| 方案 | 精度 | 成本 | 结论 |
|---|---|---|---|
| **航迹推算 + 撞墙重定位 + 近场测墙** | 全局 ±50mm 够用 | ¥0（用已有传感器） | ✅ **采用** |
| 全场挡板四边形 PnP | 远场 ±154mm | ¥0 | ❌ 精度不可用 + 退化严重 |
| 激光雷达 | 高 | ¥300+ | ❌ 规则是否允许存疑（见 docs/09 Q2） |
| 激光三角测距 | 取决于标定 | ¥12 | ❌ 明亮场馆 3m 处不可见；滤光片会废掉视觉通道 |
| 视觉里程计（下视光流） | 中 | ¥0 | ⚠️ 可选增强，M3 之后再说 |

**关键认知**：全局定位只需 ±50mm（只要知道球门方向、附近有无棋子），
真正要求精度的是**航向**（IMU，±0.5°）和**棋子相对车体的方位**（下视相机，±3mm）。
**"棋子的绝对坐标"从来没有出现在推入公式里。**

### 4.3 视觉

| 方案 | 结论 |
|---|---|
| **经典 CV 找棋子 + 小 CNN 读字** | ✅ **采用** —— 把 nncase 调试面压到最小 |
| 端到端 YOLO 检测棋子类别 | ❌ 3 个月内数据集与量化风险高 |
| 只做颜色分类不读字 | ⚠️ **降级策略 B**，作为兜底保留 |

**关键认知：颜色是免费的高价值先验。** 中国象棋红方字红、黑方字黑、底色相同，
所以"红/黑"是**颜色阈值**，不需要停车、不需要 CNN。只需推己方颜色的棋子
→ **需要读字的候选立刻减半（16 枚）**。

### 4.4 主控

> ⚠️ **设计阶段论证偏向 G431；实际采购为 STM32G474VET6。**

| 方案 | 阶段结论 | 实际 |
|---|---|---|
| STM32G431 | ✅ 有硬件 FPU，定时器资源充足 | ❌ 未采购 |
| **STM32G474VET6** | （当时未列入） | ✅ **实际采用**（G4 高端，170MHz，高分辨率定时器） |
| STM32F103C8T6 | ⚠️ 可行但无 FPU | — |
| K230 兼任 | ❌ 无 1kHz 确定性 | — |
| 自研 PCB | ❌ 3 个月来不及打样调试 | ✅ 仍成立（全部用成品模块） |

> ⚠️ **G474 的 RAM 约 128KB**，远小于设计阶段考虑的 H723（564KB）。
> 详见 [docs/13](13-主控与算力平台.md) 的内存预算分析与 [docs/16](16-最终商品清单.md) 的差异对照。

### 4.5 驱动

> ⚠️ **同 4.1：设计阶段论证偏向 BTS7960，实际采购为 TB6612 四路 D24A。**

| 模块 | 持续电流 | VM 上限 | 阶段结论 | 实际 |
|---|---|---|---|---|
| **BTS7960 / IBT-2** | **43A** | 27V | ✅ 阶段采用 | ❌ 未采购 |
| **TB6612FNG 四路 D24A** | 1.2A/通道 | 13.5V | ❌ 阶段否决 | ✅ **实际采用** |
| DRV8833 | 1.2A | 10.8V | ❌ 3S 超压 | — |
| DRV8871 | 3.6A | 45V | ⚠️ 可用备选 | — |

**设计阶段的反对理由**：本车 1.5kg 且有推板，顶墙/顶棋子/顶对方车时必然堵转；
双电机同时堵转 4–10A 灌进 TB6612 → 热保护跳闸 → **丢控制权**。

**→ 实际采用 TB6612 后，这个风险依然存在，但性质变了**：

| | 旧理解 | 实际情况（见 [TB6612 规格](../hardware/electrical/TB6612_MG513X_规格.md)） |
|---|---|---|
| 模块形态 | 裸芯片 | **四路带稳压版 D24A**，板载 5V/3.3V（RT8279 + RT9013） |
| 过温保护 | 芯片级 | **65°C 整板过温保护** |
| ⚠️ 后果 | 电机失驱动 | **同时切断 5V/3.3V 轨 → STM32 与 K230D 一起断电** |
| 电机 | 520 堵转 2–5A | MG513X 堵转 1.5–3.2A（读数待定），4 轮约 4–4.8A |

**结论：堵转保护必须做**（两种读数下堵转电流都 > TB6612 持续 1.2A）。
详见 [docs/03](03-电控与驱动系统.md) 与 [docs/17](17-实际电机参数核对.md)。

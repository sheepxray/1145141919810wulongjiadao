# 10 · 开发计划与里程碑

> 时间：**3 个月**（校赛/省赛）。核心原则：**MVP 优先 —— 先把"能得分"做出来，再加"得分最优"。**
>
> 字符识别是**优化项，不是前提**。

---

## 1. 里程碑总览

| 阶段 | 周次 | 目标 | 交付物 |
|---|---|---|---|
| **M1** | 1–4 | 底盘能动、能自主定位 | 差速底盘 + 编码器速度环 + IMU 航向环 + 航迹推算 |
| **M2** | 5–7 | **能得分（MVP）** | 前视找棋 + 下视捕获 + 两段式闭环直推 + 撞墙重定位 |
| **M3** | 8–10 | **得分最优** | 停车读字 CNN + 打分函数 + 帅/将优先级 + 送分规避 |
| **M4** | 11–12 | 稳定与对抗 | 降级策略 B、避让、堵门绕行、终场规则、满负荷压力测试 |

### ⚠️ M2 结束必须有一套完整的兜底方案

**即使 M3 的 CNN 完全失败，也要能参赛。** 这是整个计划最重要的约束。

## 2. M1 · 底盘与定位（第 1–4 周）

### 第 1 周 · 采购与设计

| 任务 | 输出 |
|---|---|
| **发出 Q1–Q8 书面问询**（[docs/09](09-待确认事项与风险.md)） | 问询记录 |
| 按 [docs/08](08-BOM物料清单.md) 采购 | 到货 |

| **★ 实测帧率基线**（见下） | 实测数据 |

> **最后两项不要拖** —— 它们都是本项目最大的技术风险：
> nncase 工具链（[docs/09](09-待确认事项与风险.md) R1），以及
> **30 FPS 能否达成（[docs/12](12-帧率与实时性.md)）**。

#### ★ 第 1 周必须完成的帧率基线

**30 FPS 是硬指标，必须最早验证，不能拖到联调阶段。**

```
1. 在 K230 上跑 firmware/k230/profiler.py
2. 记录：取帧耗时、find_blobs 耗时、SEARCH/SERVO 实际帧率
3. 回填 tools/framerate.py，把 [预估] 改成 [实测]
4. 重跑 python tools/framerate.py 确认 30 FPS 仍达标
```

**若这一步就不达标**，说明需要调整工作点（降分辨率/减 ROI），
而这会**影响相机选型与机械布局** —— 所以必须早做。

| 检查项 | 目标 | 不达标时的动作 |
|---|---|---|
| 取帧（720p） | ≤ 16ms | 降低采集分辨率 |
| SEARCH 关键路径 | ≤ 16.7ms | 减 ROI / 降处理分辨率 |
| SERVO 关键路径 | ≤ 16.7ms | 同上 |
| 连续 300 帧无衰减 | 无内存泄漏 | 查循环内分配 |

### 第 2 周 · 机械装配

| 任务 | 验证 |

### 第 3 周 · 电控bring-up

| 任务 | 验证 |
|---|---|
| 电机驱动 bring-up（BTS7960） | 正反转可控 |
| 编码器读数 | 计数正确、方向正确 |
| **堵转电流与温升测试** | 记录实测堵转电流；确认不跳保护 |
| **5V 轨跌落测试**（示波器） | 堵转时跌落 < 0.3V |
| IMU SPI 通信 | 数据稳定 |

### 第 4 周 · 控制环与定位

| 任务 | 验证 |
|---|---|
| 速度环 PID 整定 | 阶跃响应无超调 |
| 航向环 PID 整定 | 原地转向无振荡 |

| 里程计标定（[docs/05](05-定位与导航.md) §6 五步） | 方形路径闭合误差 < 100mm |

### M1 出口标准

- [ ] 车能按指令走直线、转向、到达指定点
- [ ] 航迹推算在 3m 内偏差 < 50mm
- [ ] 推板三个测试通过
- [ ] K230 能跑通一个端到端的模型推理 demo
- [ ] 堵转不导致驱动失效或 5V 跌落
- [ ] **★ SEARCH 与 SERVO 实测帧率均 ≥ 30 FPS**（[docs/12](12-帧率与实时性.md)）

## 3. M2 · MVP：能得分（第 5–7 周）

> **本阶段结束时必须有一套完整可用的方案。**

### 第 5 周 · 视觉前端

| 任务 | 说明 |
|---|---|
| 前视相机采集与颜色阈值分割 | **在真实场地上标定 HSV 阈值** |
| 圆形筛选 + 连通域 | 棋子检测 |
| 坐标变换（图像 → 车体坐标） | 需要标定相机内参 |
| 场地建图（维护棋子列表） | 简单栅格即可 |

### 第 6 周 · 接近与推入

| 任务 | 说明 |
|---|---|
| 两段式路径生成（[docs/07](07-软件架构与决策策略.md) §3） | 中间点 A + 轴向吸附 |
| 原地摆正 | 在离棋子 ≥350mm 处 |
| **第二段下视视觉伺服** | ★ 最关键的一环 |
| 过冲 120–150mm + 落位确认 | 确保整体过线 |
| 撞墙重定位 | 堵转 + 测距双条件 |

### 第 7 周 · 集成与全场测试

| 任务 | 说明 |
|---|---|
| 完整状态机联调 | SEARCH → PUSH → REPOSITION 循环 |
| **搭全尺寸模拟场地**（3m×2m + 80mm 挡板） | 必须全尺寸，不能缩小 |
| 整场跑通 | 统计进球数与用时 |
| **实现降级策略 B** | 不读字，按距离抢枚数 |

### M2 出口标准

- [ ] 能在全尺寸场地上自主找到棋子并推入球门
- [ ] 单场（3 分钟）能推入 ≥ 3 枚
- [ ] 降级策略 B 可用
- [ ] **即使视觉 CNN 不可用，也能参赛**

## 4. M3 · 得分最优（第 8–10 周）

### 第 8 周 · 数据集与训练

| 任务 | 说明 |
|---|---|
| 采集/合成棋子字形数据集 | 目标每类 ≥ 500 张（合成可放大到 2000） |
| 训练 7 类兵种分类器 | 验证集准确率 > 95% |
| **nncase 量化 + K230 部署** | **量化后重新验证准确率** |

### 第 9 周 · 识别集成

| 任务 | 说明 |
|---|---|
| 停车读字协议（[docs/04](04-视觉识别系统.md) §2.3） | 含减速/稳定/采集/加速时序 |
| 颜色预筛 + 选择性读字 | 只读己方颜色、射程内 |
| 目标打分函数（[docs/07](07-软件架构与决策策略.md) §4） | 含帅/将支配项与送分规避 |
| 落位确认与类别记忆 | 避免重复读同一枚 |

### 第 10 周 · 策略优化

| 任务 | 说明 |
|---|---|
| 帅/将优先级实测 | 验证"可达且不送分"的判断 |
| 送分规避逻辑 | 距离惩罚 + 走廊占用 |
| 时间管理优化 | 每场目标数最大化 |
| 光照鲁棒性测试 | 不同色温/亮度下的准确率 |

### M3 出口标准

- [ ] 能识别棋子分值（7 类兵种）
- [ ] 打分函数生效，优先抢高价值棋子
- [ ] 帅/将优先级正确（含"不可达则放弃"）
- [ ] 单场得分显著高于 M2

| 任务 | 说明 |

- [ ] 对手存在时仍能得分
- [ ] 现场调试流程文档化（30 分钟内可完成标定）

## 7. 关键路径

```
采购 ──→ 机械装配 ──→ 电控 bring-up ──→ 控制环 ──→ 定位标定
                                              │
                                              ↓
                    ┌─────────────────────────┴──────────┐
                    │                                    │
              视觉前端 ──→ 接近推入 ──→ MVP ★          CNN 训练
                    │         │              │            │
                    └─────────┴──────────────┴────────────┘
                                        ↓
                                   识别集成 ──→ 策略优化 ──→ 压力测试
```

**关键路径上的瓶颈**：
1. **采购周期**（第 1 周下单，最迟第 2 周必须到货）；
2. **推板验证**（机械的核心风险，M1 必须闭环）；
3. **nncase 部署**（视觉的核心风险，M1 就该验证）。

**并行策略**：机械装配与电控 bring-up 可以并行；视觉前端可以在机械完成前用桌面场景开发。

## 8. 每个阶段的"如果来不及"预案

| 阶段 | 若延期 | 砍掉什么 |
|---|---|---|
| M1 | 机械打样慢 | 先用亚克力板/现成底盘替代，功能优先 |
| M2 | 视觉伺服调不通 | 降级为开环直推 + 更大过冲（命中率下降但可用） |
| M3 | CNN 部署失败 | **直接用策略 B 参赛**，把时间投入 M4 的稳定性 |
| M4 | 时间不够 | 放弃对抗功能，保证基础得分的稳定性 |

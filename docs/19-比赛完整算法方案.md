## 0. 实机验证带来的三条硬约束

这三条是本方案的**前提**，与旧文档冲突处以本节为准。

| # | 验证结论 | 对算法的影响 |
|---|---|---|
| V1 | 麦轮**长时间/开环横移**会打滑；2026-10-21 已验证短距离闭环 `vx/vy` 回位可用 | 主路径仍以直行+转向为主；K3 等短距离纠偏启用麦轮二维平移 |
| V2 | **IMU 未到位** | 航向只能靠四轮编码器差分，漂移必须靠撞墙重定位兜底 |
| V3 | **只有 1 支 OV5640** | 无法"前视 + 下视"双相机；读字与搜索共用同一相机 |

### V1 的运动学后果

2026-10-21 修正：底盘保留完整三自由度运动学，但主路径默认仍少用横向自由度：

```text
可用：vx（前后）、vy（左右）、ω（原地转）
主路径：vx + ω；短距离闭环回位：vx + vy + ω
```

原因是麦轮辊子侧向抓地有限，长距离或开环 `vy` 容易让轮子空转、里程失真。
K3 的位置回位经过编码器闭环和航向保持验证，最终三轮位置误差为
`5.5~6.0 mm`，因此短距离二维纠偏可以安全使用。

### 轮位映射（已实测确认）

```text
A = 左前 (FL)
B = 左后 (RL)
C = 右后 (RR)
D = 右前 (FR)
```

**所有轮速组合必须按这个映射书写**，不能按 A/B/C/D 的编号顺序假设。

> ✅ 2026-10-17 逐轮目视复核：D24A 的 C、D 座与轮位**一一对应**（C=右后、D=右前）。
> 2026-10-16 曾据编码器符号推断两者互换并让固件对调，**已撤销**。上表的 A/B/C/D
> 就是轮位，下面的轮速组合不需要调整。完整对照表见
> `firmware/stm32/wulong_fw/docs/引脚分配表.md` 的「电机 / 编码器实际座序」。

| 动作 | 轮速组合 | 触发 |
|---|---|---|
| 前进 | `A+ B+ C+ D+` | `W` |
| 后退 | `A- B- C- D-` | `X` |
| 原地左转 (CCW) | `A- B- C+ D+` | `K2` |
| 原地右转 (CW) | `A+ B+ C- D-` | `R` |

## 2. 控制层算法（已实现）

代码位置：`firmware/stm32/wulong_fw/Core/Src/wulong_control.c`
接口：`firmware/stm32/wulong_fw/Core/Inc/wulong_control.h`（编译通过）

### 2.1 逆运动学（vx + ω）

```text
spin = ω · d           d = 半对角线长度（待标定）

wheel_FL = vx - spin
wheel_RL = vx - spin
wheel_RR = vx + spin
wheel_FR = vx + spin
```

其中 `d` 是「半轴距 + 半轮距」的等效力臂，单位 mm。
**必须标定**：命令转 1000 mrad（约 57.3 度），量实际角度反算 `d`。

### 2.2 速度环

每个轮子独立 PI，1 kHz：

```text
error = target_mmps - actual_mmps
duty  = Kp*error + Ki*integral
```

实际轮速由编码器 delta 换算：

```text
mm   = count * 0.129461          (1456 count/圈, φ60 轮)
mmps = mm / dt
```

固件默认 `Kp=5.0, Ki=15.0, Kd=0`（2026-10-17 台架整定，需配合 15 ms 速度反馈
低通），输出限幅 ±300‰。**标定前先确认反馈是低通的**——用 1 ms 原始反馈调参
会得到"Kp 越大越差"的假象。先让单个轮的阶跃响应无超调，再看四轮一致性。

### 2.3 里程计

```text
v  = 四轮位移均值 / dt            （前向速度）
ω  = (右轮均值 - 左轮均值) / (2d) （偏航角速度）

x += v*cos(theta)*dt
y += v*sin(theta)*dt
theta += omega*dt
```

**无 IMU 的漂移问题**：`ω` 由四轮差分得到，对打滑极敏感。
本方案用三层兜底：

1. 速度环保证四轮跟随一致（打滑时误差可控）；
2. **撞墙重定位**周期性清零（见 §4）；
3. 每次推入球门都必然贴墙，天然的重定位时机。

### 2.4 运动原语

非阻塞状态机，供上层调用：

```c
Wulong_DriveDistance(200.0f, 300.0f);   /* 前进 200mm，300mm/s */
while (Wulong_MotionIsBusy()) { Wulong_MotionUpdate(); }

Wulong_TurnAngle(1571.0f, 800.0f);       /* 左转 90 度，800mrad/s */
```

超时保护：每个原语 6 秒未完成自动 abort 并停车。

## 3. 决策层：主状态机

```text
SELF_TEST  上电自检，失败 -> DEGRADED
   |
SEARCH     巡场扫描，建图，找己方颜色棋子
   | 选目标（打分函数）
APPROACH   直行接近到中间点 A（距棋子 >=350mm）
   | 原地转向对正（推入方向指向己方球门）
ALIGN      停车读字 -> 更新分值
   | 仍值得推
PUSH       直行推进 + 过冲 120-150mm（视觉伺服）
VERIFY     确认整体过线（编码器 + 堵转）
REPOSITION 后退退出 + 撞墙重定位
   |
   +--> SEARCH

异常分支：
  堵转             -> 降 PWM 维持，上报"受阻"
  视觉失联 200ms   -> DEGRADED（策略 B）
  对方堵门         -> 换目标，稍后再来
```

### 3.1 为什么"接近"要两段

主路径仍主要靠「直行 + 转向」，以降低辊子滑移：

```text
第一段：从当前位置直行到中间点 A（A 在棋子后方 350mm，同一条推进线上）
第二段：在 A 处原地转向，把车头对准棋子->球门方向
第三段：直行推入
```

**中间点 A 必须在离棋子 >=350mm 处转向**，否则侧裙推板会扫到目标棋子。

推进方向永远吸附到场地长轴（`u = ±x`），这样：

- A 的 y 坐标 = 棋子的 y 坐标，不需要横移就能对正；
- 误差只在 x 方向，由直行距离补偿。

## 4. 定位与重定位

### 4.1 三层定位

| 层 | 手段 | 精度 | 用途 |
|---|---|---|---|
| 0 | 编码器里程计 | 短期准，长期漂 | 全程运行 |
| 1 | **撞墙重定位** | 机械级 | 每轮推入后 |
| 2 | 近场测墙（单相机） | ±5–18mm @ <1m | 辅助对正 |

### 4.2 撞墙重定位（本方案的主锚点）

```text
触发条件：堵转信号 + 前视/近场测距 < 阈值
动作：
  沿墙法向的位置清零
  相对墙的航向清零
```

**为什么这是最强锚点**：推棋子入球门必然贴端墙，
每轮得分的动作天然带来一次绝对定位。零算力、零成本。

### 4.3 航向的兜底

无 IMU 时航向漂移来自左右轮滑移差。缓解手段：

1. 转向时用编码器闭环，转够角度就停（不靠时间盲转）；
2. 每次贴墙把航向清零；
3. 单次推入路径短（<3m），漂移量可接受。

## 5. 视觉层

### 5.1 单相机分时复用

只有 1 支 OV5640，必须**分时**承担两种任务：

| 状态 | 相机朝向 | 处理 | 分辨率 |
|---|---|---|---|
| SEARCH / APPROACH | 前视 | 颜色 blob 找棋子 | 720p->640×360 |
| ALIGN（停车） | 前视/俯视 | 读字 | ROI |
| PUSH | 前视 | 视觉伺服横向偏差 | 320×160 ROI |

**读字必须停车**：透视压缩 + 卷帘错位 + 运动模糊，移动中读不了。

### 5.2 两级识别

```text
第一级（移动中）：颜色阈值 -> 圆形筛选 -> 候选 + 红/黑
     | 只保留己方颜色，32 -> 16
第二级（停车时）：小 CNN -> 7 类兵种
```

**颜色是免费先验**：红方字红、黑方字黑，阈值即可分，无需停车。

### 5.3 降级

CNN 部署失败 / 背面朝上 -> **策略 B**（不读字，按距离抢枚数）。
这是硬要求：**K230 完全不工作，车也必须能得分。**

## 6. 目标打分

```text
priority = w_v * E[value] + w_n + w_g * P(king)
         - w_d * dist_to_goal
         - w_c * corridor_congestion
         - w_r * risk_to_opponent_goal
         - w_o * opponent_proximity
         - w_u * uncertainty
```

| 权重 | 初值 | 说明 |
|---|---|---|
| `w_v` | 1.0 | 期望分值（用概率分布，不用 argmax） |
| `w_n` | 3.0 | 枚数是独立判据 |
| `w_g` | 50.0 | 帅/将支配项 |
| `w_d` | 0.02/mm | 推程 3m 扣 60 |
| `w_c` | 15/个 | 走廊有棋子会撞散 |
| `w_r` | 极大 | 送分风险 |
| `w_u` | 按方差 | 不确定性惩罚 |

**核心原则**：

1. 帅/将优先级最高，**但前提是"可达 + 不送分"**；
2. 推进方向永远朝己方球门，**任何往对面推都是负收益**；
3. 低置信度做 3 帧投票，再不行就跳过。

## 7. 安全设计

| 风险 | 处置 |
|---|---|
| 堵转（顶墙推棋子是正常工况） | 目标速度非零且实际约 0 超 200ms -> PWM 降到 30% 维持，上报"到位" |
| TB6612 过温 | 堵转保护压住发热；逻辑轨可选独立供电 |
| 低压 | ADC 监测，<10.5V 报警 |
| 急停 | PC6 拉低，四路输出关断 |
| K230 失联 | 心跳超时 200ms -> 策略 B |
| 对方堵门 | 换目标，稍后再来，不做对抗性接触 |

## 8. 时间预算

单场 180s：

| 阶段 | 时间 |
|---|---|
| 自检 | 5s |
| 搜索建图 | 20s |
| 单目标周期 | 15–22s（横移取消后转向更慢一点） |
| **可完成目标** | **约 5–7 个** |

**优化方向**：

1. 挑高价值目标，不追求推完；
2. 顺路多推（宽口推板可一次带多枚，取决于 Q8）；
3. 减少读字次数（颜色预筛已减半）。

## 11. 一句话总结

> 主路径采用**直行 + 原地转向**，短距离回位使用已验证的**麦轮 vx/vy 闭环平移**；
> 用**编码器速度环 + 撞墙重定位**顶替缺席的 IMU；
> 用**单相机分时复用**顶替缺席的第二支相机；
> 用**颜色预筛 + 期望值打分**把有限时间花在高价值目标上；
> 永远保留**不依赖视觉的策略 B**，保证 K230 挂了也能得分。

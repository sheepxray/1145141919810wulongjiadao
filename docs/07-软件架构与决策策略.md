# 07 · 软件架构与决策策略

---

## 1. 双核职责切分

| | STM32G431 | K230 |
|---|---|---|
| 职责 | 硬实时运动控制、状态机、决策 | 图像处理、CNN 推理 |
| 循环 | 1 kHz（控制）/ 100 Hz（决策） | **30 FPS**（见 [docs/12](12-帧率与实时性.md)） |
| 语言 | C（HAL + 寄存器） | Python（CanMV）/ C++ |
| 失效影响 | 全车失控 | 视觉降级 |

**耦合只有一个 UART**（921600，见 [docs/11](11-通信协议.md)）。
接口面最小 = 调试最容易。

### 1.1 ⚠️ 跨核数据流：只保留最新帧

**这是最容易翻车的地方。** STM32 以 1 kHz 跑控制环，K230 以 30 FPS 出视觉结果，
两者频率差 33 倍。如果中间用队列缓存，会出两个问题：

| 问题 | 后果 |
|---|---|
| 队列积压 | STM32 拿到的是**过期**的视觉结果 → 车按"几十毫秒前的场地状态"控制 |
| 阻塞等待 | 控制环被视觉拖慢 → 丢掉 1 kHz 的实时性 |

**正确做法（两侧都要做）**：

```c
/* STM32 侧：只保留最新一条视觉消息，不排队 */
typedef struct {
    volatile uint8_t  fresh;      /* 有新数据 */
    int16_t x_mm, y_mm;           /* 棋子相对位置 */
    uint32_t timestamp;
} vision_latest_t;

static vision_latest_t g_vision;

/* UART 中断里：直接覆盖，不排队 */
void on_target_list(int16_t x, int16_t y) {
    g_vision.x_mm = x;
    g_vision.y_mm = y;
    g_vision.fresh = 1;
    g_vision.timestamp = HAL_GetTick();
}
```

```python
# K230 侧：同理，丢弃过期帧
class LatestFrame:
    def put(self, f):
        self.frame = f          # 直接覆盖
    def get(self):
        f, self.frame = self.frame, None
        return f
```

**控制环读取时检查新鲜度**：

```c
if (g_vision.fresh && (HAL_GetTick() - g_vision.timestamp) < 100) {
    /* 用视觉数据做伺服 */
    g_vision.fresh = 0;
} else {
    /* 数据过期 -> 降速或保持上一指令，绝不盲推 */
}
```

> **延迟的量化分析见 [docs/12](12-帧率与实时性.md) §7**：
> 只保留最新帧时位置滞后约 11mm，占推板半开口 82mm 的 14%，余量充足；
> 但若队列积压到深度 5，滞后会涨到 45mm（54%），足以把棋子推歪。

## 2. 主状态机

```
                    ┌──────────┐
                    │  SELF_   │  上电自检（docs/03 §6）
                    │  TEST    │  失败 → DEGRADED
                    └────┬─────┘
                         ↓
                    ┌──────────┐
              ┌────→│  SEARCH  │  巡场，前视找己方颜色棋子
              │     └────┬─────┘  建图，选下一个目标
              │          ↓
              │     ┌──────────┐
              │     │  APPROACH│  第一段：开到中间点 A
              │     └────┬─────┘  （在 A 处原地旋转摆正）
              │          ↓
              │     ┌──────────┐
              │     │  ALIGN   │  停车 → 下视读字 → 更新类别
              │     └────┬─────┘  决定是否值得推（打分函数）
              │          ↓
              │     ┌──────────┐
              │     │  PUSH    │  第二段：下视伺服直线推进 + 过冲
              │     └────┬─────┘
              │          ↓
              │     ┌──────────┐
              │     │ VERIFY   │  确认棋子整体进入球门区
              │     └────┬─────┘
              │          ↓
              │     ┌──────────┐
              └─────┤REPOSITION│  倒车退出 + 撞墙重定位
                    └──────────┘
                         │
              ┌──────────┴──────────┐
              ↓                     ↓
        ┌──────────┐          ┌──────────┐
        │ COLLISION│          │ STUCK    │  对方车堵门 / 卡住
        │ _AVOID   │          │ _AVOID   │  → 换目标，稍后再来
        └──────────┘          └──────────┘

        ┌──────────┐
        │ DEGRADED │  视觉失效 → 策略 B（不读字，抢枚数）
        └──────────┘
```

## 3. 两段式接近的路径生成

### 3.1 推进方向吸附到场地长轴

**这是关键简化。** 让推进方向吸附到场地长轴：

```
u = (±1, 0)    指向己方球门
```

好处：

| 好处 | 说明 |
|---|---|
| 棋子 y 坐标在推进中不变 | 中间点不会因 clamp 落到场外 |
| 顺带得到"沿墙纵推"的天然形态 | 贴墙棋子自动落在可行的推进路线上 |
| 几何误差最小 | 轴向推进不需要侧向分量 |

### 3.2 中间点 A 的选取

```
A = P − u · L        L = 350mm

只对 x 做 clamp（若 P 离远端太近，L 减到能放进场内）
y 完全由棋子决定 —— 因为是轴向推进，A.y = P.y，不存在落到场外的问题
```

### 3.3 可行性判定

| 条件 | 处理 |
|---|---|
| `P.y − car_half < wall + clearance` | 标记 `wall_hug` → 走**贴墙纵推模式**（docs/05 §5） |
| `A` 周围半径 140mm 内有其它棋子 | A 再后移 150mm，或换对侧入场角；仍不行则换目标 |
| 推入走廊内有其它棋子 | 打分函数降低优先级（会撞散） |
| 贴墙纵推但棋子在对方半场 | ⚠️ **跳过** —— 会把它推向对面球门 = 送分 |
| 车放不下 | 放弃，标进地图，不再尝试 |

> 32 枚里放弃 2–3 枚贴死角的不影响胜负。

### 3.4 在 A 处摆正

**必须在离棋子 ≥350mm 的地方完成旋转** —— 侧裙推板离得太近会扫到目标棋子。

## 4. 目标打分函数

### 4.1 平局判据是层级式的

```
总分 (Σ分值)                    ← 第一优先
  → 进球总数 (枚数)              ← 第二判据，有独立价值
    → 帅/将归属                  ← 第三判据，但是支配项
      → 60 秒金球加赛
```

**打分函数必须反映这个层级。**

### 4.2 函数

```
priority(P) =  w_v · value(P)                  # 分值（第一判据）
             + w_n · 1                          # 枚数（第二判据，独立价值）
             + w_g · is_king(P)                 # 帅/将支配项
             − w_d · dist(P, 己方球门)           # 距离惩罚（推程越长越易失误）
             − w_c · corridor_congestion(P)      # 推入走廊里的其它棋子（会撞散）
             − w_r · risk_to_opponent_goal(P)    # ★ 推向对面球门的风险
             − w_o · opponent_proximity(P)       # 对手正在争抢
```

建议初值（之后按实测调）：

| 权重 | 取值 | 理由 |
|---|---|---|
| `w_v` | 1.0 | 分值即分数 |
| `w_n` | 3.0 | 枚数是第二判据，1 分棋子也有独立价值 |
| `w_g` | **50.0** | 支配项 —— 拿帅/将 = 所有平局场景自动赢 |
| `w_d` | 0.02/mm | 3m 推程扣 60 分 |
| `w_c` | 15.0/个 | 走廊里有棋子会撞散 |
| `w_r` | **非常大** | 见 4.4 |
| `w_o` | 10.0 | 对手近则避让 |

### 4.3 帅/将的正确表述

⚠️ **"开局第一目标必是帅/将"是错的。**

帅/将的优先级 = max，**但前提是"可达 + 不送分"**。

| 情形 | 正确决策 |
|---|---|
| 帅/将在己方半场、路径干净 | ✅ 最高优先级，立刻去抢 |
| 帅/将在对方半场、推程 3m | ⚠️ 高风险 —— 失误会把 10 分送给对面 |
| 对方也在抢帅/将 | ⚠️ 评估是否来得及；来不及则退而抢己方半场高分与多枚 |

**核心权衡**：鲁莽直冲可能送 10 分给对面，**比不拿更糟**。

### 4.4 ★ 推入对方球门 = 给对方送分

这是本赛题**最容易被忽略的战略核心**。

赛题是"把棋子推入**己方**球门区，按分值累计"。推论：

| 推论 | 含义 |
|---|---|
| 推进方向**永远**朝向己方球门 | 任何"往对面推"的动作都是负收益 |
| **失控漂移的棋子是礼物** | 一次没控住的推击把 10 分棋子拱进对面门 = **−20 分摆动** |
| 靠近对方半场的棋子成本极高 | 推程 3m + 送分风险 → 距离惩罚要强 |

**这再次说明第二段必须闭环** —— 闭环不只是为了提高命中率，
更是为了**避免把棋子推歪到对面**。

> 高级玩法（**校赛阶段不做**）：把对方高分棋子从对方球门附近推离，做"拒止"。
> 极易变成送分。

### 4.5 对手是动态障碍

对手车可能**堵在你的球门区做防守**。你没有对抗手段（禁冲撞），只能：

1. 检测到拥堵 → 换目标 → 稍后再来；
2. 绕行；
3. 耐心等待。

**状态机里必须有"拥堵检测 → 换目标 → 稍后再来"的循环。**

### 4.6 终场规则

临近终场要有 **commit or abort** 判断：

> 宁可少推一枚，也不要最后一刻把一枚高分棋子留在**对方球门边上**
> —— 可能被对方顺手补进自己门。

## 5. 降级策略 B（视觉失效兜底）

**这是必须有的**，因为：

- nncase 量化部署有失败风险；
- 若 Q2 答案是"棋子可能背面朝上"，整套识别链路直接作废。

### 5.1 策略内容

不读字、不做分值识别，改为：

```
目标 = 离己方球门最近的棋子
      → 扫掠式把己方半场的棋子朝己方球门推
      → 优先抢「进球总数」（平局第一判据）
```

### 5.2 触发条件

| 条件 | 动作 |
|---|---|
| K230 串口握手失败 | 直接进策略 B |
| CNN 推理连续 N 次超时 | 进策略 B |
| 识别置信度持续低于阈值 | 进策略 B |
| 检测到棋子"无字面"占比高 | 进策略 B（应对 Q2） |

### 5.3 为什么策略 B 也能拿分

因为平局第二判据是**进球总数**。即使不识别分值，
**多推几枚 1 分的棋子也能在总分打平时决定胜负**。

## 6. 时间管理

3 分钟（180s）的粗略预算：

| 阶段 | 时间 | 说明 |
|---|---|---|
| 自检 | 5s | 含 IMU 静止标定 |
| 搜索建图 | 20s | 巡场一圈，前视扫描 |
| 每个目标周期 | 18–25s | 接近 + 读字 + 推入 + 重定位 |
| **可完成目标数** | **约 6–8 个** | 180 / 22 |

**这意味着时间很紧。** 优化方向：

1. **不要追求推完所有棋子** —— 挑高价值的 6–8 枚；
2. 若赛制分上下半场且有中场休息，可重新规划；
3. **顺路多推**：宽口盒式推板天然具备一次带多枚的能力（待确认 Q8 是否允许）；
4. 减少读字次数（颜色预筛已经减半）。

## 8. 调试接口（有线，禁止无线）

C11 禁止遥控。**调试链路必须是有线的**：

| 接口 | 用途 |
|---|---|
| USART1 (PA14/PA15) | 调试串口，接 USB-TTL |
| SWD | 下载 + 实时变量观察 |

**注意**：不要用带蓝牙/WiFi 的开发板做"临时调试"——
即使不用，模块的存在也可能被判定为具备遥控能力。

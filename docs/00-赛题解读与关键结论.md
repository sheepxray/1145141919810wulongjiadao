## 2. 由约束推出的关键设计判断

### 判断一：全局定位精度要求低，**航向**和"相对棋子"的精度要求高

推入方向 = 棋子相对车体的方位（下视相机测，±3mm 级）+ 车体绝对航向（IMU 测，±0.5° 级）。

> ⚠️ 实际 kit 暂未含**下视相机**与 **IMU**（见 [16](16-最终商品清单.md) §3 后置补购）。这两条链路的精度目前由「单 OV5640 前视 + 轮速航向」兜底，10-07 视觉/动力验证后按 [10](10-开发计划与里程碑.md) §0 判据决定是否补购。

注意这里**没有出现"棋子的绝对坐标"**。全局定位只需精确到"知道球门在哪个方向"和
"附近有没有棋子"，**±50mm 完全够用**。这大幅降低了对全局定位的要求 —— 也是本方案
敢用纯航迹推算而不上激光雷达的原因。

### 判断二：底盘方案已裁决为麦克纳姆轮（2026-09-28 按实际采购更新）

暗扣：早期版本驳麦轮、选差速，理由是「侧裙推板可以消掉差速车推入段的偏航/侧滑」。但 2026-09 实际采购到手的是 **60mm 麦轮 ×4 + 4×MG513X 电机**（见 [16 商品清单](16-最终商品清单.md)），并已在 [10 计划](10-开发计划与里程碑.md) §0 明确「不再保留差速分支」。因此当前底盘方案 = **麦克纳姆轮全向底盘**，原「麦轮三项代价」论证降级为必须在验证中消化的风险清单：

- 4 电机 = 成本/质量/故障点成倍 → 初代底板快速上电验证，10-14 第二版再优化；
- 仅 3D 打印时麦轮辊子粗糙、横移侧滑 → 动力/视觉验证阶段实测滑移，作为定位漂移闸门（10 §0 IMU 判据）；
- 麦轮不改变车宽 → 判断三仍成立：贴墙容错仍靠「窄车体 + 宽推板」，与底盘形式无关。

> 保留判断三（车宽无关）与盒式推板思路不变；只是把「差速还是麦轮」这一选择改由实际到货决定。

### 判断三：贴墙容错窗口**与车宽无关** —— 这是本设计最重要的一处洞察

棋子贴侧墙时，车体横向可用的对准窗口：

```
约束 (a) 推板罩住棋子 : car_y − jaw_half ≤ r           （r = 棋子半径）
约束 (b) 车体不撞墙   : car_y ≥ car_half + clearance

窗口 = (r + jaw_half) − (car_half + clearance)
```

若推板不超出车体（`jaw_half = car_half`），则 `car_half` **被完全消掉**：

```
窗口 = r − clearance   （与车宽无关！）
```

`tools/geometry.py` 实测证实了这一点：推板开口从 150mm 排到 200mm，窗口**恒为 17.5mm**。
**把车体做宽完全无效。**

正确做法是让**推板比车体宽**。设悬伸量 `overhang = jaw_half − car_half`：

```
窗口 = r + overhang − clearance
```

| 车体宽 | 推板宽 | 悬伸 | 窗口 |
|---|---|---|---|
| 190mm | 195mm | 2.5mm | 20.0mm |
| **150mm** | **195mm** | **22.5mm** | **40.0mm** |
| 140mm | 195mm | 27.5mm | 45.0mm |

**结论：车体做窄（140–160mm），推板做满 195–200mm。** 这是零成本收益。

### 判断四：双主控是必需品，不是过度设计

- 汉字识别（CNN 推理）需要 NPU，STM32 跑不动；
- 4 路编码器 + EKF + 双环 PID 需要 1kHz 级确定性和硬实时中断，Linux SoC 给不了。

两边职责清晰、耦合只有一个串口，是最稳的切分。

### 判断五：把"帅/将"当成独立战略目标

平局第一判据是"进球总数"，**第三**判据才是"帅/将归属"。但帅/将是**支配项**：

- 拿下帅/将 = 在所有平局场景下自动获胜；
- 丢掉帅/将 = 在所有平局场景下自动落败。

所以其期望价值远超 10 分面值。**但要注意前提**：帅/将的优先级 = max，
**前提是"可达 + 不送分"**。若它在对方半场、推程 3m 且失误会把 10 分送给对面，
鲁莽直冲可能是负收益。正确表述是"可达且不送分时优先，否则退而抢己方半场高分与多枚"。

## 3. 重要更正：挡板测距的几何

**早期版本写道**："挡板上下边缘的像素间距只与距离有关，与相机高度和俯仰角无关，
即 `d = H·f/Δy`。" —— **这个说法是错的**，只对了一半。

正确的完整投影关系（相机高 `h`、俯仰角 `θ` 向下为正、挡板高 `H`、水平距离 `d`）：

```
α_bot = atan(h / d)           挡板底(地面)的俯角
α_top = atan((h − H) / d)     挡板顶的俯角

Δy = f · [ tan(α_bot − θ) − tan(α_top − θ) ]
```

- **θ = 0 时**：`Δy = f·H/d` → **相机高度 h 确实被消掉** ✓
- **θ ≠ 0 时**：上述化简不成立，**俯仰角并没有被消掉** ✗

`tools/geometry.py` 的实跑数据（相机 OV5640+2.8mm）：

| h | θ | 真值 d | 近似式 `H·f/Δy` 反解 | 误差 |
|---|---|---|---|---|
| 150mm | 0° | 0.50m | 0.500 | 0.0% |
| 150mm | 20° | 1.50m | 1.396 | **−6.9%** |
| 250mm | 10° | 0.50m | 0.559 | **+11.9%** |
| 250mm | 30° | 1.50m | 1.314 | **−12.4%** |

最大误差 **17.3%**。所以：

- 近似式**只能**用于相机水平安装，或已标定俯角后的修正；
- 本仓库的定位实现一律使用**完整投影的数值反解**（`solve_range_from_pixels`）。

### 附带的量程结论

即便用正确的反解，测距精度仍随距离平方恶化（边缘定位噪声按 2px 计）：

| 距离 | 像素间距 | 测距不确定度 |
|---|---|---|
| 0.5m | 306 px | **±5.2mm** |
| 1.0m | 162 px | ±18.5mm |
| 1.5m | 110 px | ±40.1mm |
| 3.0m | 56 px | **±154.4mm** |

**结论：视觉测墙只能做近场（< 1m 精度可用）。全场挡板 PnP 方案因此被否决**
（远场精度不可用，且存在单墙退化、平行墙无法定 6DOF、遮挡、反光等失效模式）。

而贴墙纵推需要 ±10mm 级的横向精度 —— **这不能由视觉测墙提供**，
必须靠"机械贴墙 + ToF"闭环（见 [docs/05](05-定位与导航.md)）。

### 不要用激光做定位

1mW 650nm 一字线在明亮体育馆里 3m 处几乎不可见；要靠窄带滤光片抗环境光，
但加了 650nm 窄带滤光片后就**只能看见激光、看不见别的**，等于毁掉正常视觉通道。
且结构化光的精度依赖激光器-相机的基线标定，标定漂移后全盘失效。

**激光只为满足"必须搭载"这条规则**：串限流电阻、实测功率 ≤0.7mW、低位向前安装、
清晰标识。**不接入定位链路。**

## 5. 一句话总结

> 用**赛题自带的挡板**做近场绝对定位，用**做窄的车体 + 做宽的推板**换取贴墙容错，
> 用**双相机**分开"看墙"与"读字"两个几何需求，用**第二段闭环直推**保证命中，
> 把**帅/将**提到最高战略优先级（前提是可达且不送分），全程不参与对抗性接触。

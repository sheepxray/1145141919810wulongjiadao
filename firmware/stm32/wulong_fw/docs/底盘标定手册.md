# 底盘标定手册

> 对应算法方案：[docs/19](../../../docs/19-比赛完整算法方案.md) §9 阶段 1–4。
> 对应固件：`Core/Src/wulong_control.c` + `Core/Src/main.c` 的标定控制台。
>
> **目标**：把速度环增益、半对角线力臂、有效轮径、转向极性四项标定出来。
> 这四项完成前，所有转向角度和直行距离都不可信。

---

## 1. 控制台命令

先烧录最新固件，打开串口 `115200 8N1`。所有标定命令在**控制台模式**下运行。

| 命令 | 作用 |
|---|---|
| `CV` | 开/关控制台模式（开启后跑 1 kHz 闭环速度环） |
| `CS <0-3> <mmps>` | 设定某个轮的目标线速度，如 `CS 0 200` |
| `CG <0-3> <kp> <ki> <kd>` | 设定速度环增益 |
| `CH <mm>` | 设定半对角线力臂 |
| `CM <val>` | 设定 mm/count |
| `CP` | 打印四轮实测速度、位姿、标定参数，以及 `ENCQ rejects=` 噪声限幅计数（2026-10-17 起） |
| `CZ` | 位姿与编码器清零 |
| `S` / `E` | 立即停车并退出控制台 |

轮编号：`0=左前(A) 1=左后(B) 2=右后(C) 3=右前(D)`。

> `CS/CG/CH/CM/CP` 是多字符命令，**必须带分号或以回车结束**，
> 例如 `CS 0 200;` 或 `CP;`。

---

## 2. 第一步：速度环整定

**先单个轮，再四轮。**

> ⚠️ **速度反馈必须先低通，否则 PID 调不出来。** 1 kHz 控制周期下，
> `0.129461 mm/count` 意味着 200 mm/s 的轮子每毫秒只走 1~2 个计数，
> 原始反馈只有 **129 / 259 mm/s 两个值**（台阶 = 设定值的 65%）。
> 直接把这种信号喂给 PID，环路会来回抖，**Kp 越大越糟**——这也是
> 2026-10-17 之前反复调不出增益的真正原因。
>
> 从 `wulong-fw 2026-10-17 speed-lpf` 起，固件对速度反馈加了一阶低通
> （`WULONG_SPEED_FILTER_TAU_S = 15 ms`），等效把测量窗口从 1 ms 拉长到
> 15 ms，台阶降到约 9 mm/s，代价是 15 ms 附加滞后。`CP` 的 `SPD` 用的是
> 同一个滤波后的值，所以看起来也会稳很多。
>
> 里程计不受影响——它累加的是原始计数。

### 2.1 操作

四轮架空，然后：

```text
CV
CZ
CS 0 200;
CP;
```

`CP` 会每行打印四轮速度。反复发 `CP;` 观察第 0 号轮（左前）的实测速度。

### 2.2 判据

| 现象 | 处理 |
|---|---|
| 实测速度在 200 mm/s 附近稳定，无明显振荡 | ✅ 通过 |
| 速度远低于 200 且不涨 | `Kp` 太小，加大 |
| 速度上下大幅振荡 | `Kp` 太大，减小 |
| 速度慢慢爬升、稳态有静差 | 加 `Ki` |

参考整定顺序（每次只改一个参数）。**当前固件默认值就是台架调好的结果**：

```text
CG 0 5 15 0;     当前默认值：200 mm/s 下 0.6 s 到 90%，误差 +0.2%
CG 0 5 6 0;      想保守一点可以降 Ki
CG 0 8 15 0;     想更快可以提 Kp（上升 0.59 s，稳态略低）
```

实测参考（wheel A，空载，目标 200 mm/s，2026-10-17）：

| kp | ki | 稳态 | 纹波 | 到 90% |
|---|---|---|---|---|
| 1.6 | 3 | 199.1（-0.4%） | 2.5% | 1.31 s |
| 5 | 15 | 200.3（+0.2%） | 1.8% | **0.59 s** |
| 8 | 3 | 194.5（-2.8%） | 1.3% | 0.59 s |

四轮同时跑（目标 200 mm/s）：wheel0~3 = 200.7 / 200.7 / 200.7 / 200.4，
离散度 0.15%。

> **判据不是"速度等于设定值"，而是"阶跃无超调、无持续振荡"。**
> 有静差可以接受，有振荡不行。
>
> ⚠️ **整定前先确认速度反馈已低通**（`speed-lpf` 及之后的固件）。用原始 1 ms
> 反馈去调 `Kp` 只会得到"Kp 越大越差"的假象——那是量化噪声，不是环路特性。

### 2.3 四轮一致性

四个轮子分别整定后，同时给同样目标：

```text
CS 0 200; CS 1 200; CS 2 200; CS 3 200; CP;
```

判据：四轮实测速度应接近（差异 <10%）。

**若某一路明显偏低或偏高**，先查该路编码器线序与轮子机械阻力，
不要用不同的增益去"补偿"机械问题。

> ⚠️ **先排除符号错误，再谈增益。** 若某一路实测速度与目标**反号**、或直接冲到
> 300 mm/s 以上，那不是增益问题，而是该路编码器符号与电机方向不一致——速度环
> 变成了正反馈，增益越调越糟。此时按
> [电机Bring-up测试.md](电机Bring-up测试.md) §5.12 复核符号，并核对
> [引脚分配表.md](引脚分配表.md) 里的「电机 / 编码器实际座序」
> （2026-10-16 实测 C、D 两座互换，固件已在通道层补偿）。

### 2.4 高精度轮速环（2026-10-20 起）

固件在原有 PI 基础上增加了三项工程措施：

| 措施 | 参数/行为 | 作用 |
|---|---|---|
| 速度前馈 | `1.02 permille/(mm/s)` | 先给出接近稳态的 PWM，PI 只修残差 |
| 静摩擦补偿 | `18 permille` | 补偿减速箱和辊子的低速死区 |
| 条件积分抗饱和 | 饱和且误差继续推向限幅时停止积分 | 防止贴 30% 上限后积分积满 |
| 速度反馈 | 3 点中值 + 25 ms 低通 | 抑制 1 ms 计数量化与单点尖峰 |
| C 路鲁棒滤波 | 3 点中值 + 40 ms 低通 | C 路编码器已知串扰更强，单独加长窗口 |

默认增益仍为 `Kp=5 / Ki=15 / Kd=0`。调参时先检查四轮都在
`100 / 150 / 200 mm/s` 附近；如果整体响应过冲，先降低 `Kp`，
不要用不同的四轮增益掩盖机械差异。前馈和摩擦补偿是
`wulong_control.h` 中的常量，改变后必须重新编译烧录。

#### 自动阶跃测试

四轮架空后发送 `STUNE`。固件会自动运行 100 / 150 / 200 mm/s
三个阶段；每段 700 ms 稳定、800 ms 采样，结束后自动停车。测试结果
保存在 RAM 并在串口打印：

- `mean`：稳态平均速度；
- `ripple`：采样窗内峰峰值；
- `std`：标准差；
- `duty`：平均 PWM 千分比；
- `rise`：从阶跃开始到达到目标 90% 的时间。

2026-10-20 实测（四轮架空，最终参数）：

| 目标 | 最大均值误差 | A/B/D 纹波 | C 纹波 | 90% 上升时间 |
|---|---:|---:|---:|---:|
| 100 mm/s | 0.45% | 15.3~19.6 mm/s | 22.4 mm/s | 47~57 ms |
| 150 mm/s | 0.32% | 14.2~19.3 mm/s | 30.4 mm/s | 37~40 ms |
| 200 mm/s | 0.23% | 16.0~21.4 mm/s | 39.8 mm/s | 18~29 ms |

## 3. 第二步：直行距离标定（有效轮径）

### 3.1 操作

在平坦地面上量出一条 **1 米** 直线。然后：

```text
CV
CZ
CS 0 200; CS 1 200; CS 2 200; CS 3 200;
```

让车走约 1 米后立即 `S`。用 `CP` 读位姿中的 `x`。

### 3.2 计算

```
真实距离 L_real = 1000 mm
里程计读数 L_odo = CP 里的 x

新的 mm_per_count = 0.129461 × (L_real / L_odo)
```

例如里程计读了 950mm，说明轮径被低估：

```text
0.129461 × 1000/950 = 0.136275
CM 0.136275;
```

然后重新走一次 1 米验证。

### 3.3 判据

| 项 | 目标 |
|---|---|
| 1 米距离误差 | < 1% |
| 直线横向偏移 | 尽量小；明显偏说明左右轮速不一致 |

> ⚠️ 麦轮直行的有效轮径和游标卡尺量的直径不同（辊子受力变形）。
> **必须用实测距离反算，不要用 60mm 直接算。**

## 4. 第三步：转向角度标定（半对角线）

这是**最关键、也最容易错**的一项。它决定所有转向角度的准确性。

### 4.1 操作

四轮架空或放在地面，车中心做标记。然后：

```text
CV
CZ
CS 0 -200; CS 1 -200; CS 2 200; CS 3 200;
```

让车原地转，直到**目视转过约 90°**，立即 `S`。用 `CP` 读 `th`（单位 mrad）。

### 4.2 计算

```
目标角度 theta_cmd = 1571 mrad   (90°)
实测角度 theta_meas = CP 里的 th

新的 half_diag = 旧 half_diag × (theta_meas / theta_cmd)
```

例如转了 90° 但里程计只报 1400 mrad（偏低），说明力臂取大了：

```text
100 × 1400/1571 = 89.1
CH 89.1;
```

### 4.3 更准的做法

目视 90° 有误差。更准的方法：

1. 在地面画一个十字标记；
2. 车从指向"北"开始；
3. 命令转到指向"东"；
4. 用手机量角器或在地面画好的角度线上比对。

### 4.4 判据

| 项 | 目标 |
|---|---|
| 命令 90°，实测偏差 | < 2° |
| 左右各转 90° 后 | 航向对称，无明显累积误差 |

> 若左转和右转误差不对称，说明四轮之间存在机械差异
> （轮径、阻力），这是麦轮底盘的正常现象，先保证对称平均误差达标。

---

## 5. 第四步：转向极性确认

确认"左转时编码器角度增加"：

```text
CZ
CS 0 -200; CS 1 -200; CS 2 200; CS 3 200;
CP;
```

判据：`CP` 的 `th` 应为**正值**（逆时针为正）。

若为负值，说明左右轮的 `d` 符号或编码器符号反了，需要检查：

1. 四轮编码器符号（`Wulong_GetEncoder`）；
2. 左右轮的目标速度分配（`body_to_wheel_speeds`）。

---

## 6. 标定结果回写

运行时通过 `CH`/`CM`/`CG` 改的值**断电即失效**。
标定稳定后，把最终数值写回代码常量：

| 参数 | 写回位置 |
|---|---|
| 半对角线 | `wulong_control.h` 的 `WULONG_HALF_DIAG_MM` |
| mm/count | `wulong_control.h` 的 `WULONG_MM_PER_COUNT` |
| 速度环增益 | `wulong_control.c` 的 `Wulong_ControlInit()` |

改完后重新编译烧录。

## 7. 标定检查表

- [ ] 单轮速度环：阶跃无振荡
- [ ] 四轮符号复核：给正目标时四路 `SPD` 同号且落在目标附近（见 §2.3 的警告）
- [ ] 四轮速度一致性：差异 <10%
- [ ] 直行 1m：误差 <1%
- [ ] 转向 90°：误差 <2°
- [ ] 左转为正（CCW）
- [ ] 参数回写代码并重新烧录

四项全部通过后，才可以在 `Wulong_DriveDistance` / `Wulong_TurnAngle`
之上搭建状态机（[docs/19](../../../docs/19-比赛完整算法方案.md) §3）。

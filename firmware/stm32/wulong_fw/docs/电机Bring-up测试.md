# 电机 Bring-up 测试

> 对应固件：`Core/Src/main.c`（测试代码位于 `USER CODE` 区）。
> 目标：在车轮架空的前提下，逐路验证 D24A → MG513X 的方向、PWM、
> 编码器、STBY 软急停和电池采样。

## 1. 安全默认值

固件上电后：

- `STBY = 低`，D24A 四路输出全部关闭；
- 四路 PWM compare 全部为 `0`；
- 不自动转动任何电机；
- 串口测试命令有硬上限：占空比 `300‰`，持续时间 `5000 ms`；
- 命令超时或收到 `S` / `E` 后立即回零并拉低 `STBY`。

> 测试时必须把车轮架空。不要带载落地做第一轮 bring-up。

## 2. 串口接线

调试串口为 `USART1 = PC4(TX) / PC5(RX)`，`115200 8N1`。

PWLINK2 自带串口代理转发能力，可用其 `TX / RX / GND`：

| PWLINK2 | STM32G474 | 说明 |
|---|---|---|
| `RX` | `PC4` | PWLINK2 接收 STM32 发出的数据 |
| `TX` | `PC5` | PWLINK2 向 STM32 发送命令 |
| `GND` | `GND` | 必须共地 |

- IO 参考电压选 `3.3 V`；
- 不要用 PWLINK2 的 `5V` 给已经由 D24A 供电的 STM32 反灌；
- 如果 PWLINK2 的虚拟串口在设备管理器里有黄叹号，先用 PowerWriter 客户端
  修复 USB 串口驱动，再打开对应 COM 口。

## 3. 烧录与连接

1. 接好 D24A 的 `Vin+ / -`、电机 A-D、编码器 A-D、`STBY=PC6`。
2. 先不接电机动力，测量 D24A 的 `5V` 和 `3.3V` 是否正常。
3. 用 PWLINK2 通过 SWD 烧录 `MDK-ARM/wulong_fw/wulong_fw.hex`。
4. 烧录后打开 115200 串口，应看到（第一行是固件标识，用于确认烧的确实是新版本）：

```text
wulong-fw 2026-10-16 cd-remap
BOOT: motor
BOOT: rx
BOOT: imu
IMU ready=1 (ICM-20602 on SPI2)
WULONG motor test ready
Default: STBY low, all PWM=0. Type H for help.
```

> 如果没有 `wulong-fw ...` 这一行，说明烧进去的还是旧固件，串口命令修复尚未生效。

> `BOOT: motor / rx / imu` 三行是分段标记：卡在哪一行就是哪一段初始化挂住，
> 便于区分"完全没输出"是没上电、还是初始化里某一步死住。

> 串口接收是否真的在进数据，看 `STAT` 里的 `rx=<n>` 累计字节数：发几次命令后
> `rx` 不涨，说明 USART1 一个字节都没收到，先查 `PC5`(RX) / 上位机 TX / 共地。

5. 发送 `H`，确认命令表打印正常。

### 3.1 串口输入无反应（2026-10-09 修复）

**根因**：`CommsTask` 原先每 2 ms 调用一次 `HAL_UART_Receive(..., Timeout=0)`
轮询单字节。115200 baud 下一个字节间隔约 87 µs，而 USART1 的 FIFO 被
`HAL_UARTEx_DisableFifoMode()` 关闭，两次轮询之间到达的二十多个字节全部丢失。
多字符命令（`IC`、`II`）只会收到第一个字符，表现为「发命令完全没反应」。
单字符命令（`S`、`H`）有时能碰巧生效，`IC` 这类必然失败。

**修复**：USART1 改为中断接收（`HAL_UART_Receive_IT`）→ 128 字节环形缓冲 →
`CommsTask` 排空缓冲解析；并实现 `HAL_UART_ErrorCallback` 清除 overrun 标志、
重新挂载接收，避免一次溢出后 RX 永久失效。

另加两项便利与诊断：

- 行空闲 150 ms 后自动执行命令，兼容不发送 CR/LF 的串口助手；
- `ECHO` 开关（原样回显收到的字节）、`STAT` 增加 `rx=<n>` 累计接收字节数，
  以及开机时的 `BOOT: motor / rx / imu` 分段标记。

> `RXDIAG` 是 2026-10-09 那一版的临时诊断输出，当前固件已由
> `STAT` 的 `rx=<n>` 取代。

## 4. 串口命令

| 命令 | 作用 |
|---|---|
| `H` | 打印命令表 |
| `ARM` | 拉高 `STBY`，允许显式 `RUN` |
| `DISARM` | PWM 回零，拉低 `STBY` |
| `S` / `STOP` | 立即停止并解除使能 |
| `E` / `ESTOP` | 软件急停，等同停止 |
| `A+` / `A-` 到 `D+` / `D-` | A-D 路快速点动，默认 `10%`、`800 ms` |
| `A+ 1500` | A 路正转 `10%`、`1500 ms` |
| `A+ 15 1500` | A 路正转 `15‰`、`1500 ms` |
| `RUN A + 15 1500` | 显式测试，必须先 `ARM` |
| `P` / `1` | A 路正转 10%、800 ms（兼容逐字符串口工具） |
| `F` | A 路 **100% 正转、2000 ms**；架空车轮专用，硬超时后立即停止 |
| `L` | **四轮同时 100% 正转、2000 ms**；架空车轮专用，硬超时后立即停车并解除使能 |
| `N` / `2` | A 路反转 10%、800 ms（兼容逐字符串口工具） |
| `3` / `4` | B 路正转 / 反转，10%、800 ms |
| `5` / `6` | C 路正转 / 反转，10%、800 ms |
| `7` / `8` | D 路正转 / 反转，10%、800 ms |
| `T` | 自动依次测试 A+ A- B+ B- C+ C- D+ D-，并打印每步编码器增量 |
| `W` | 四轮同时逻辑正转、20% 占空比，持续行驶直到 `S/E` |
| `X` | 四轮同时逻辑反转、20% 占空比，持续行驶直到 `S/E` |
| `K1` / 串口 `K1` | 四段定时序列，每段 2 秒：前进 → 左平移 → 右平移 → 后退 |
| `K2` | 四轮直行，5 秒升到 100%，再满速保持 10 秒后停车 |
| `K3` | 陀螺仪校准 → 随机角速度原地旋转 5 秒 → 回航向/回位置 |
| `STUNE` | 自动测试 100/150/200 mm/s 四轮速度环并记录均值、纹波、PWM、90% 上升时间 |
| `IR [ms]` | 格式化 IMU 报告：原始值、换算值、姿态角、航向、累计角、三轴零偏；默认 2000 ms |
| `Q` | 打印 A/B/C/D 四路编码器计数 |
| `ENC` | 打印 A-D 四路编码器当前计数 |
| `Z` | 四路编码器计数清零 |
| `V` | 打印电池电压（mV，按 1/11 分压换算） |
| `STAT` | 打印 armed / active / tick |

占空比单位为千分比：`10 = 1%`，`100 = 10%`，`300 = 30%`。

`IR` 会关闭电机和 `IT` 数字遥测，每 2000 ms 输出五行中文报告；
再发送一次 `IR` 关闭。报告中的航向以启动后校准时刻的 X 轴方向为 0°，
逆时针为正。

> 如果串口工具的“字符模式”只可靠发送单个字符，优先使用
> `P` / `F` / `N` / `Q` / `T` / `S` / `E` / `H`。多字符命令必须以 `;`、回车或换行结束。

> ⚠️ `F` / `L` 命令绕过 30% 软件限幅，直接输出 100% 占空比 2 秒。
> 只允许在**四轮架空、车体固定**时使用；地面行驶、车轮受阻或 D24A
> 已经偏热时不要发送 `F` / `L`。

## 5. 推荐测试顺序

> **座序前提（2026-10-17 逐轮目视复核）**：D24A 的 C、D 座与轮位**一一对应**
> （C 座 = 右后轮、D 座 = 右前轮），下面所有命令里的 A/B/C/D 就是
> **左前 / 左后 / 右后 / 右前**，且物理上一一对应。
> 完整对照表见 `引脚分配表.md` 的「电机 / 编码器实际座序」一节。
>
> ⚠️ **轮位只能靠"逐轮点动 + 目视"确认。** 编码器符号自洽**不能**替代目视：
> 方向线取反会同时翻转电机极性和计数符号，两种设置都自洽。
> 2026-10-16 就是因为只看符号、没看轮子，误判了 C/D 插座互换（见 §5.12 的更正记录）。

### 5.1 只测 A 路

```text
Z
ENC
A+ 10 800
ENC
A- 10 800
ENC
S
```

判据：

- `A+` 时电机 A 正转；
- `A-` 时电机 A 反转；
- `ENC A` 的计数正负随方向变化；
- 其他 B/C/D 路不应转动；
- D24A 不发热，电流不异常抬升。

### 5.2 B/C/D 逐路重复

每次替换命令首字母：

```text
B+ 10 800
B- 10 800
C+ 10 800
C- 10 800
D+ 10 800
D- 10 800
```

每路都确认“只有目标电机转动”。如果命令 A 却 B 转，说明通道映射或
D24A 侧接线标号错误，先改线，不要继续加占空比。

### 5.3 编码器方向核对

对每路分别执行：

```text
Z
A+ 10 1500
ENC
Z
A- 10 1500
ENC
```

目标：同一路正转和反转的计数符号相反；手转输出轴一圈时，
单相应约为 `364 P/r`，四倍频应约为 `1456 count/r`。

字符模式只支持单字符时，A 路用：

```text
DIP1 = OFF
Q
P
Q
N
Q
S
```

判据：`P` 后的 `ENC A` 相对第一个 `Q` 必须有变化，`N` 后的变化方向相反。

### 5.4 四路逐台单字符测试

串口工具只能稳定发送单字符时，按下面顺序操作：

```text
Q     记录四路初始计数
1     A 正转
Q
2     A 反转
Q
3     B 正转
Q
4     B 反转
Q
5     C 正转
Q
6     C 反转
Q
7     D 正转
Q
8     D 反转
Q
S     停止并解除使能
```

判据：

- 发 `1/3/5/7` 时，只有对应电机正转；
- 发 `2/4/6/8` 时，只有对应电机反转；
- 每一步 `Q` 中，对应编码器计数应变化，其余三路应基本不变；
- 同一路正转与反转的计数增量符号相反。

### 5.5 四路自动轮测

确认四路都能单独动作后，发送单字符：

```text
T
```

固件会依次执行：

```text
A+ → A- → B+ → B- → C+ → C- → D+ → D-
```

每一步为 10% 占空比、800 ms，间隔 300 ms，并打印：

```text
AUTO A+
DONE A+ delta=...
AUTO A-
DONE A- delta=...
...
AUTO TEST DONE
```

判据：

- 每一步只有对应电机转动；
- `delta` 绝对值应明显大于 0，同一路正反转符号相反；
- 任一步异常时立即发 `S` 或 `E`，自动序列会中止；
- 四路 `delta` 数量级应接近；若某一路接近 0，先查该路编码器线序。

### 5.6 首次落地直行

四路单机测试和 `T` 自动轮测通过后，才做行驶测试。

第一次必须先把车架空：

```text
Q
W
Q
S
```

判据：

- 四轮应朝同一物理前进方向转；
- `Q` 中 A/B/C/D 四路计数都应变化，正负号一致；
- 若 C 的物理方向与 A/B/D 相反，回到 C 路方向修正，不要落地；
- 若某一路不动或计数不变，先按单路测试排查。

架空确认后再落地低速直行：

```text
W
```

确认车向前直行且不偏转，再发：

```text
S
```

当前 `W/X` 为 20% 占空比，是首次行驶的安全值。确认直行方向、线性和 D24A
温升都正常后，再提高占空比或加入横移、自转和速度闭环。

### 5.7 K1 用户按键（启动视觉接近）

`K1` 是 M 板用户按键，对应 STM32 **PD8**：GPIOD、Port D、Pin 8，
LQFP100 封装的**物理第 55 脚**。按下为低电平，芯片内部上拉。
固件做 30 ms 消抖；按键按下后启动 `VA` 等价的 K230 视觉接近模式。
只有 K230 已运行、视觉帧正常，并且其它测试/CV 控制台均空闲时才会启动。

串口 `K1` / `SEQ` 仍保留原来的四段定时测试，每段固定 2 秒、20% 占空比：

```text
phase 0  FWD       A+ B+ C+ D+
phase 1  STRAFE_L  A- B+ C- D+
phase 2  STRAFE_R  A+ B- C+ D-
phase 3  BWD       A- B- C- D-
```

轮位映射为已确认的 `A=FL, B=RL, C=RR, D=FR`。横移符号由
[docs/03](../../../docs/03-电控与驱动系统.md) §3.1 的麦轮逆运动学推出，
并用已实测的原地转向组合（左转 = `A- B- C+ D+`）反查校验过轮序映射。

> ⚠️ **横移是已知薄弱项**：三维打印的麦轮辊子侧向抓地不足，实测会打滑
> （[docs/19](../../../docs/19-比赛完整算法方案.md) §0 / §4.3）。本序列用于
> 重新验证该结论；若 `STRAFE_L` 实际往右跑，把 phase 1/2 的符号整体对调。

串口命令 `K1`（别名 `SEQ`）只用于诊断四段序列，不改变物理 K1 键的
“启动视觉接近”含义。

串口过程信息：

```text
K1 SEQ START: FWD STRAFE_L STRAFE_R BWD (2s each)
K1 PHASE FWD
K1 PHASE STRAFE_L
K1 PHASE STRAFE_R
K1 PHASE BWD
K1 SEQ DONE
```

首次验证顺序：

1. K230 运行 `vision_approach.py`，四轮架空；
2. 按一次 `K1`，发送 `VI` 应看到 `active=1`；
3. 确认视觉帧持续更新，电机根据 `err_pm` 输出；
4. 发 `E` 应立即停止并关闭视觉接近模式；
5. 需要诊断四段轮速时，改发串口命令 `K1`。

### 5.8 K2 四轮直行线性升速并满速保持（15 秒）

`K2` 是 M 板第二个用户按键，对应 STM32 **PD9**，按下为低电平，同样有
30 ms 消抖。

按下一次 `K2` 后，四轮按直行方向组合运行：

```text
A+ B+ C+ D+
```

运行总时长为 **15000 ms**：

```text
duty_permille = min(elapsed_ms * 1000 / 5000, 1000)
```

即 0 秒为 0%，1 秒为 20%，2.5 秒为 50%，5 秒到 100%；
之后保持 100% 运行 10 秒，在第 15 秒停车并拉低 `STBY`。
该动作会绕过正常 30% 限幅，
只允许在四轮架空、车体固定的条件下测试。

串口过程信息：

```text
K2 FORWARD 0->1000 in 5000 ms, hold 10000 ms
K2 t_ms=1000 duty=200
...
K2 t_ms=5000 duty=1000
...
K2 t_ms=15000 duty=1000
K2 FORWARD DONE
```

判据：

- 按下 K2 后四轮应同时朝车辆正前方转动；
- 四轮应同时起转、同时停；
- 第 15 秒结束后必须自动停，不需要再发 `S`；
- 若某一路方向相反，使用 `FLIP <0-3>` 修正整轮极性；
- 该测试必须架空；第 5~15 秒会持续 100% 占空比，风险很高。

`K1` 方阵运行期间按 `K2` 不会叠加动作；`K2` 运行期间按 `K1` 也会先停止
当前转向，再启动方阵。任何时刻发 `S` 或 `E` 都会立即停车。
串口或调试器触发 `K2` 等价于按键。

### 5.9 K3 陀螺仪随机旋转与自动回归

`K3` 是 M 板第三个用户按键，对应 STM32 **PD10**，按下为低电平。

按下一次后，固件自动执行：

1. 停止所有其它测试，拉低 `STBY`；
2. 静止采集 **2000 点**陀螺仪零偏；
3. 随机选择左转/右转和 `2200~2999 mrad/s` 的目标角速度；
4. 通过轮速 PI 闭环原地旋转 **5000 ms**；
5. 制动 250 ms，用陀螺仪执行“短脉冲 → 滑行 → 静止验证”回正；
6. 每次回正后停车静止 350 ms 复核航向，未通过才允许下一次脉冲；
7. 若中心偏移为 20~120 mm，则转向原点、前进回到原点，再恢复起始航向；
8. 偏移超过 120 mm、任一阶段超时或收到 `S/E` 时立即停车。

串口或调试器也可触发 `K3`，等价于按键。状态与结果可从 `STAT`
的 `k3=` 字段查看，例如 `running / OK / ESTOP / POSITION_LIMIT / ...`。

判据：

- 校准期间车轮必须静止，2 秒内不得有人为转动；
- 5 秒旋转方向随机，角速度受 30% 占空比上限约束；
- 旋转后必须自动回零航向，最终航向误差建议 `< 10 mrad`；
- 原地位姿偏移建议 `< 20 mm`；
- 任何超时或位置误差超限必须自动停并拉低 `STBY`。

> 纯旋转阶段 `vx=0`，固件不会把左右轮平均里程积分成平移，避免轮速差异
> 和编码器噪声制造虚假位置偏差。

> 该测试需要车轮落地并具有正常纵向抓地力。车轮架空时只能验证校准、
> 状态机和电机顺序，IMU 不会随车体真实旋转。

### 5.10 四路短时同步

只有单路全部通过后，才做四路短时低占空比测试：

```text
ARM
RUN A + 10 800
RUN B + 10 800
RUN C + 10 800
RUN D + 10 800
S
```

这条命令序列只逐路启动，不会同时启动四路；用于确认连续操作不会触发
电源跌落或 D24A 异常。

### 5.11 STBY 软急停

运行任一路时发送：

```text
E
ENC
STAT
```

判据：

- 电机立即断电滑行；
- `STBY` 回低；
- `STAT` 显示 `armed=0`；
- 发送 `ARM` 后仍不能自动恢复转动，必须重新发运动命令。

### 5.12 闭环符号复核（判定四轮符号是否真的对齐）

开放环点动只能看出"编码器有没有动"，**要判断符号对不对必须用闭环**：符号接反时
速度环会变成正反馈，转速直接顶到饱和。这是最快、也最不含糊的判据。

```text
CV
CS 0 200; CS 1 200; CS 2 200; CS 3 200
CP
```

判据：

- 四路 `SPD` 都应落在 200 mm/s 附近（±5%），并且**符号一致**；
- 任一路读数与目标反号、或明显冲到 300 mm/s 以上，就是该路编码器符号与该路
  电机方向不一致（正反馈），必须先修正再落地；
- 测完发 `S` 停止、再发 `CV` 退出控制台。

> 2026-10-16 记录：C、D 两路符号同时相反，闭环下 C 在 100 mm/s 目标直接飙到
> 2400 mm/s、D 稳定顶在 -335 mm/s。当时**据符号推断**插座互换并让固件对调；
> 2026-10-17 逐轮目视复核证明推断有误（插座本来就一一对应），**对调已撤销**，
> 四路符号仍全为正。教训：轮位必须目视确认，符号自洽不能替代。

### 5.13 编码器噪声限幅（固件保护，2026-10-17 起）

从 `wulong-fw 2026-10-17 cd-remap-lim` 开始，速度环加了一道**合理性限幅**：
单次 1 ms tick 里由编码器增量折算出的速度若超过 `WULONG_MAX_WHEEL_MMPS`
（默认 500 mm/s，定义在 `wulong_control.h`），就判定为开关噪声，
**丢弃这次采样**——保持上一次速度估计，且这一段不计入里程。

作用：多电机同时运行时编码器线会被 PWM 灌入噪声（实测约 19000 counts/s，
几乎等于 10 kHz PWM 的边沿率）。没有限幅时控制环会跟着噪声把占空比顶到
上限，表现为某一路突然飙到 ±2000 mm/s 以上；有限幅后既不会窜车，
里程计也不会把垃圾积进去。

是否触发过，看 `CP` 新增的那一行：

```text
ENCQ rejects=<n> (encoder samples dropped as impossible)
```

`rejects` 只要在涨，就说明线束确实在收噪声。**限幅只是兜底，不是修复**——
根因仍要按 §8 的接地 / 走线 / 104 电容去解决。

### 5.14 `FLIP`：整轮翻转（2026-10-17 起）

**逐路符号测试有一个盲区**：如果某一路的电机极性和编码器**同时**反了，
编码器照样读出正数，符号测试全绿，但轮子实际是倒着转的。B 和 D 两路都栽在
这一点上——B 直到跑直行才被发现。

`FLIP <轮号 0-3> [0|1]` 专门解决这个：它**同时**反转该轮的方向线**并**翻转该轮的
编码器符号，也就是"这个轮子是反装的"这一件事的完整表达。

```text
FLIP 1        切换 wheel1（B）的极性
FLIP 1 1      设为翻转
FLIP 1 0      取消翻转
```

判断方法只有一个——**驱动整车、看轮子实际往哪转**：

```text
CV
CSA 150          四轮同时慢速前进
```

哪一路倒转就 `FLIP <该路>`，再跑一次，直到四轮同向。

> 当前四路的默认值（`wulong_control.c` 的 `s_flip[]`）：**A=0, B=1, C=1, D=0**。
> 确认无误后请把结论写回这里的默认值，别只留在运行态。

## 8. 常见故障

| 现象 | 优先检查 |
|---|---|
| 四路都不转 | `STBY` 是否为高；D24A 是否有 VM；是否已 `ARM` |
| 发 A 命令但错路转 | A-D 电机线和编码器线是否一一对应；C/D 插头是否互换（见 §5 座序前提） |
| 电机转但编码器不变 | 编码器 VCC/GND 线序；E1A/E1B 是否接对 |
| 编码器计数方向反 | A/B 相是否接反；软件方向符号是否统一 |
| 闭环转速顶到最大或与目标反号 | 该路编码器符号与电机方向不一致（速度环成了正反馈）；按 §5.12 复核，再核对座序与固件映射 |
| 加大 `Kp` 反而稳态误差更大、响应更慢 | 速度反馈被 1 ms 窗口量化了：200 mm/s 时只有 129 / 259 两个值（台阶 129 mm/s）。固件已加 15 ms 低通（`cd-remap-lim` 之后的 `speed-lpf` 版本），详见 `底盘标定手册.md` §2 |
| 逐路符号全为正、但整车直行时某个轮子倒转 | 该轮电机极性和编码器**同时**反了，符号测试查不出来。用 `FLIP <该轮>`（见 §5.14），再目视确认四轮同向 |
| 点动某一路时，另一路编码器也跟着计数（车已架空） | 空闲通道 H 桥悬空，把运行通道的 PWM 噪声耦合进了它的编码器线；属台架假象，闭环行驶时不出现。彻底消除需把编码器线与动力线分开走线并按星型接地 |
| 多路同时闭环运行时，某一路实测速度明显低于目标（如 250 目标只到 213），或偶发飙到 ±2000 mm/s 以上 | 该路编码器信号被其它通道的 PWM 灌入。特征：飙出值约 19000 counts/s，几乎等于 PWM 的 20000 边沿/秒，说明编码器输入被 PWM 直接驱动而非轮子在转。<br>**MCU 侧已排除**：单独驱动该路时 `CCR` 与引脚高电平占比一致、相邻引脚无串通。<br>处理顺序：① 按 `接口定义.md` §3.4 重做星型接地，编码器 GND 不要与动力回流共用；② 编码器线束与动力线束分开走；③ 逐个按紧 4 个 6P 插头 |

> ⚠️ **测占空比时不要只读一次 `CCR`。** 速度环 1 kHz 输出可能在大范围内摆动，
> 单次采样会读到瞬时峰值（实测出现过 `CCR=30.0%` 而引脚高电平占比只有 20.4% 的情况）。
> 判据要用"引脚采样一段时间的高电平占比"或固定时间窗的编码器增量，不要用单点快照。
| 一上电就转 | `STBY` 是否被跳线帽硬拉高；方向线是否被外部上拉 |
| 串口无回显 | `PC4/PC5` 是否交叉；PWLINK2 串口驱动是否为正常 COM |
| 电池电压明显不对 | D24A `ADC` 是否接 PA4；1/11 分压口径是否一致 |

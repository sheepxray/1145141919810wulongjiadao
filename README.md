# 智能车光电象棋对抗 — 设计与开发仓库

第十五届全国大学生光电设计竞赛 · 赛题 1

本仓库存放参赛智能车的**机械设计、电控设计、视觉算法、软件与测试文档**。

---

## 一句话方案

一台 **差速驱动** 智能车，前装 **带侧裙的盒式推板**，用 **前视相机近场测挡板** + **下视相机停车读字**，
由 **K230 视觉协处理器 + STM32G431 运动主控** 双核驱动，全程自主完成
"搜索 → 选目标 → 两段式接近 → 闭环推入 → 撞墙重定位"。

## 关键设计结论

| 项目 | 结论 | 依据 |
|---|---|---|
| 底盘 | **差速 + 2× JGB37-520 12V（霍尔编码器）** | 侧裙推板消掉了麦轮的必要性；少一半电机与故障点 |
| 车体宽度 | **做窄（140–160mm）**，推板做满 195–200mm | 贴墙容错窗口**与车宽无关**，只取决于推板悬伸量 |
| 推板 | **盒式：宽开口 + 侧裙 + 柔性贴地** | 车体 150 时容错窗口 40mm（对 17.5mm） |
| 驱动板 | **BTS7960 (IBT-2) ×2** | TB6612 连续 1.2A，带不动堵转 2–5A 的 520 电机 |
| 主控 | **STM32G431**（有硬件 FPU） | 浮点 PID/EKF 不用软浮点 |
| IMU | **ICM20602** | 零偏稳定性优于 MPU6050；廉价 MPU6050 多为贴牌 |
| 相机 | **2× OV5640**（前视 + 下视，卷帘快门） | 读字时完全静止 → 无卷帘错位、无运动模糊 |
| 定位 | **航迹推算 + 撞墙重定位 + 近场测墙** | 全局只需 ±50mm；精度要求其实在航向与"相对棋子" |
| 激光 | 650nm 1mW，**仅作合规装备，不接入定位** | 见 [docs/05](docs/05-定位与导航.md) |
| 全重 | **987 g**（限值 1500 g） | `python tools/mass_budget.py` |
| 总价 | **¥807**（预算 ¥2000） | 同上 |
| 外廓 | 225 × 190 × 170 mm（限值 250×200×180） | 同上 |

## 三个反直觉但重要的发现

以下是本仓库用可运行脚本校核出来的、与直觉相反的结论：

1. **把车体做宽对贴墙容错完全无效。** 对准窗口 = `棋子半径 + 推板悬伸量 − 离墙间隙`，
   车体半宽被消掉。推板开口从 150 排到 200mm，窗口恒为 17.5mm。
   正确做法是**车体做窄、推板做宽**。

2. **`d = H·f/Δy` 这个挡板测距公式不能无条件使用。** 它只在相机水平时精确；
   俯角 30°、相机高 250mm 时误差达 **17.3%**。本仓库一律用完整投影数值反解。

3. **单相机在几何上确实能兼顾"看远墙"和"读汉字"**（俯角窗口约 14°），
   但代价是挡板落在畸变最大的画面边缘、且远近场曝光难以兼顾。
   因此仍推荐双相机，单相机作为预算极紧时的备选。

## 性能指标：30 FPS

**要求：30 FPS 帧处理速度。** 完整分析见 [docs/12](docs/12-帧率与实时性.md)。

达标有三个**不可妥协**的前提：

| # | 前提 | 违反的后果 |
|---|---|---|
| 1 | **采集用 720p** | 5MP 全分辨率**只有 15 fps**，硬件上就卡死，与算力无关 |
| 2 | **处理前降采样** | 像素数是 720p 的 5 倍 |
| 3 | **两台相机分时复用** | 任何时刻只有一台需要 30 FPS |

| 模式 | 采集 | 处理分辨率 | 可达 | 余量 |
|---|---|---|---|---|
| SEARCH（前视） | 720p @60 | 640×360 | 120 FPS | 4× |
| SERVO（下视） | 720p @60 | 320×160 ROI | 384 FPS | 12× |

**延迟**（比帧率更重要的量）：只保留最新帧时位置滞后 **11mm**，占推板半开口 82mm 的 14%，余量充足。

**若资源不够，砍搜索、保伺服** —— 下视伺服直接决定推入命中率，前视搜索只是慢一点。

> ⚠️ 上述耗时是 **[预估]**。要真正"保证"30 FPS，必须在 K230 上跑
> [`firmware/k230/profiler.py`](firmware/k230/profiler.py) 实测并回填。

## 工具（全部可运行，且都带自测）

```bash
python tools/geometry.py                          # 相机几何校核
python tools/mass_budget.py                       # 质量与预算校核
python tools/framerate.py                         # 30 FPS 帧率预算分析
python tools/protocol.py                          # 通信协议实现 + 自测
python firmware/stm32/reference/kinematics.py     # 差速运动学 / PID / 航迹推算
python firmware/stm32/reference/scoring.py        # 目标打分函数
```

`firmware/k230/profiler.py` 需在 **K230 真机**上运行，用于把上述预估值换成实测值
（在 PC 上运行会提示如何在设备上部署）。

**采购相机之前先跑 `geometry.py`** —— 它会告诉你所选镜头能否看到远处挡板。

这几个脚本不是纸面文档，它们的自测**实际捕获过 4 个真实缺陷**，已全部修正：

| # | 缺陷 | 发现方式 |
|---|---|---|
| 1 | 挡板测距公式"与俯仰角无关"是错的（实为只在相机水平时成立，俯角 30° 时误差 17.3%） | `geometry.py` 数值对照 |
| 2 | 协议 `MAX_PAYLOAD=64` 与自身规范矛盾（`TARGET_LIST` 满 8 项需 70 字节） | `protocol.py` 带宽核算 |
| 3 | 串口解析器"朴素状态机"会被噪声中的假帧头吃掉真实帧，导致**一帧噪声后持续丢包** | `protocol.py` 噪声测试 |
| 4 | STM32 引脚冲突：IMU 的 SPI1（PA6/PA7）与编码器 TIM3 冲突 | 画引脚表时发现 |

## 一句话方案

一台 **差速驱动** 智能车，前装 **带侧裙的盒式推板**，用 **IMX219 双相机做 1080p@30 视觉**，
由 **RK3588 视觉平台 + STM32H723 运动主控** 双核驱动，全程自主完成
"搜索 → 识别字符 → 计算优先级 → 两段式接近 → 闭环推入 → 撞墙重定位"。

## 关键设计结论

| 项目 | 结论 | 依据 |
|---|---|---|
| 底盘 | 差速 + 2× JGB37-520 | 侧裙推板消掉了麦轮的必要性 |
| **车体宽度** | **做窄 150mm**，推板做宽 195mm | ★ 贴墙容错窗口**与车宽无关**，只取决于推板悬伸 |
| 推板 | 盒式：宽开口 165 + 侧裙 30 + 柔性贴地 | 贴墙容错 40mm（对 17.5mm） |
| 驱动 | **BTS7960** ×2 + **INA240 限流** | TB6612 会热保护跳闸；不限流会烧电机 |
| 主控 | **STM32H723** | RAM 18×，为迭代留余量 |
| 视觉 | **RK3588 + 双 IMX219** | CPU 算力 25×，2× 帧率余量 |
| 电池 | 3S 1500mAh 25C | 压降 0.75V（判据是内阻不是容量） |
| 定位 | 航迹推算 + 撞墙重定位 + 近场测墙 | 全局只需 ±50mm |

## ★ 反直觉的发现（都经脚本验证）

1. **把车体做宽对贴墙容错完全无效。** 窗口 = `棋子半径 + 推板悬伸 − 离墙间隙`，
   车体半宽被消掉。推板开口从 150 排到 200mm，窗口**恒为 17.5mm**。

2. **`d = H·f/Δy` 挡板测距公式不能无条件用。** 只在相机水平时精确；
   俯角 30°、相机高 250mm 时误差 **17.3%**。

3. **1080p@30 的瓶颈是 CPU 不是 NPU。** K230 的 NPU 有 6 TOPS 但跑不动，
   因为图像预处理在 CPU 侧（800 vs 20000 MOPS）。

4. **换更大的电池解决不了电流问题。** 堵转 5A 会让电机 86 秒烧毁，
   只能用限流（INA240）解决。

5. **下视相机不能垂直向下装。** 垂直时可见地面仅 0–76mm，
   看不到推板前方 100–250mm 的棋子。必须前倾 60°。

6. **argmax 会高估不确定的目标。** 55% 确定是车时，argmax 说 9 分，
   期望值说 7.19 分 —— 后者才诚实。

```bash
python tools/power_budget.py          # 第1轮：电流/堵转热分析/限流验证
python tools/compute_budget.py        # 第2轮：控制环负载/内存/架构对比

python tools/piece_value.py           # 第4轮：期望值/优先级算法
python tools/sketchup_model.py        # 第5轮：SketchUp 建模脚本生成
python tools/geometry.py              # 相机几何校核
python tools/mass_budget.py           # 质量与预算（最终选型）
python tools/framerate.py             # 帧率预算（通用方法论）
python tools/protocol.py              # 通信协议 + 自测
```

**采购前先跑 `sketchup_model.py` 和 `mass_budget.py`** —— 它们校核尺寸与质量。

### 脚本自测捕获的真实缺陷

| # | 缺陷 | 发现方式 |
|---|---|---|
| 1 | 挡板测距公式"与俯仰角无关"有误（俯角 30° 误差 17.3%） | `geometry.py` 数值对照 |
| 2 | 协议 `MAX_PAYLOAD=64` 与自身规范矛盾 | `protocol.py` 带宽核算 |
| 3 | 串口解析器被假帧头吃掉真帧，导致持续丢包 | `protocol.py` 噪声测试 |
| 4 | STM32 引脚冲突：IMU SPI1 与编码器 TIM3 冲突 | 画引脚表 |
| 5 | **相机立柱漏算**，总高 99.5 → 160mm | `sketchup_model.py` 尺寸校核 |
| 6 | 850mAh 与 1500mAh 内阻被称"相当"（实际差 29%） | `power_budget.py` |
| 7 | 18AWG 被判"不够"却推荐（混淆峰值与持续载流量） | `power_budget.py` |

## SketchUp 建模

```bash
python tools/sketchup_model.py          # 生成 hardware/mechanical/sketchup/build_robot.rb
```

在 SketchUp 2026 中：**窗口 → Ruby 控制台 → 粘贴脚本 → 回车**

模型包含三层板、轮系、电机、盒式推板（含侧裙）、50mm 相机立柱、双相机、电子件占位。
**参数化生成** —— 改尺寸后重跑即可，不用手工改模型。
